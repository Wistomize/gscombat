## Purpose

定义已生成伤害报告中单把候选武器精炼调整的计算与展示行为。局部请求必须与完整反事实分析给出相同结果，同时保留其他报告内容，并隔离快速操作、场景变化和请求失败造成的过期数据。

## ADDED Requirements

### Requirement: 单候选分析与完整比较一致

系统 MUST 接收完整固定伤害场景、一个候选武器标识及精炼等级，只返回该候选的伤害、收益比例、标识、精炼和服务端求得的基线。候选可用性、武器等级、装备效果条件及队伍联动 MUST 与完整武器比较一致；系统 MUST NOT 为局部请求生成其他武器、词条或成长项比较。

#### Scenario: 调整具有队伍增益的候选武器精炼

- **WHEN** 对同一合法场景请求某候选精炼 2 的局部结果，并以同样精炼执行完整分析
- **THEN** 两者该候选的伤害和收益比例一致
- **AND** 候选武器对其他反应参与者的合法增益参与重算，原场景及基线装备保持不变

### Requirement: 非法候选请求可识别地失败

系统 MUST 对非 1 至 5 的整数精炼、未知或不兼容的武器、无法满足现有候选资格的武器及不具备命座资格的伤害指标返回 HTTP 400 和明确错误说明。真实服务内部错误 MUST 保留失败状态，不伪装成零伤害成功结果。

#### Scenario: 提交非法精炼或武器

- **WHEN** 请求精炼 0、6、1.5，或请求角色无法装备的武器
- **THEN** 接口以 HTTP 400 拒绝，不返回候选成功结果

### Requirement: 精炼调整仅更新相应武器行

Web MUST 在精炼变化后保留基线、结算面板、轨迹、词条及成长项结果，只更新对应候选并按既有排序规则重排。等待与失败 MUST 标识在对应武器行；失败时保留上次成功值及其精炼，不能把旧数值标为新精炼结果。选择已成功展示的相同精炼且无待处理变更时 MUST 不发起重算。

#### Scenario: 一行计算失败

- **WHEN** 一把武器的精炼请求失败
- **THEN** 其余报告仍可阅读和操作
- **AND** 该行展示失败状态及上次成功精炼的结果，用户可以重试

### Requirement: 旧请求不能覆盖当前报告

Web MUST 将局部结果归属到生成报告的固定场景，并保证同一武器只采纳最后一次选择；不同武器的合法响应 MUST 可以分别合并。改变角色、配置、动作、敌人、Buff 或重新生成完整报告后，旧局部响应 MUST NOT 覆盖新结果。

#### Scenario: 同武器响应乱序

- **WHEN** 用户依次选择精炼 2、3，但精炼 2 的响应最后返回
- **THEN** 该行最终保持精炼 3 的结果

#### Scenario: 不同武器先后返回

- **WHEN** 两把武器均在同一报告中调整精炼，响应以相反顺序返回
- **THEN** 两行都保留各自最新结果，不相互覆盖

#### Scenario: 请求期间更换指标

- **WHEN** 旧报告的精炼请求未完成，用户更换指标并生成新报告
- **THEN** 旧请求的成功或失败均不改变新报告
