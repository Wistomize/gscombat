## Context

动机和用户范围见 [proposal.md](proposal.md)。现有 `analyzeWeaponComparison` 通过替换 primary 后调用正式 `evaluateScenario` 求值；`AnalysisPreparation` 仅在一次分析内按不可变 Build 身份复用基础面板。现有套装资格、前后台与来源去重已经统一，但套装计数仍需覆盖基础治疗加成、角色能力及各效果解析入口，不能仅在展示层替换效果ID。

本设计跨 HTTP、计算和 Web 生命周期，需 design。沿用 [ADR-0014](../../../docs/adr/0014-use-one-authoritative-scenario-metric-evaluation-path.md) 的单一求值链路。实现阶段新增异步比较执行边界 ADR，记录以下取舍；本轮仅创建本 change 的规划文件。

## Goals / Non-Goals

**Goals:** 保持原始属性与真实场景，支持当前角色四件套/2＋2比较；核心结果优先；候选只算目标标量；用可追踪的缓存命中与求值计数证明复用。

**Non-Goals:** 不引入后台作业数据库、消息队列或线程池；不把比较候选保存为实际装备；不扩展队友换套和辅助指标；不借机重写全部分析架构。

## Decisions

### 0. 已批准修订：四星主词条及部位取优

本节优先于后文“等原始属性/原始词条聚合共享”的无条件表述。按候选必要四星件数枚举5选2或5选4；仅复制受影响部位主词条为本地快照四星16级值，副词条对象和原Build不修改，缺件不补。共享准备生命周期内缓存每个原Build的主词条变体；各套装在同变体上加件数覆盖，从而复用基础属性但重新计算套装派生及队伍贡献。相同实际属性变体去重，伤害相等按固定枚举顺序取首项。每个变体独立应用暴击调配并保留胜出项的折算说明。

结果新增可选四星部位字段，旧客户端可忽略；Web显示部位和用户指定原文提示，总说明明确主词条例外。升级缓存规则版本，候选排名仍一套一行。单候选更新内部可求值5/10次，不再用“一次候选求值”等同“一次伤害求值”；基准与完整报告不重复。验证真实快照、手工分配最大值、副词条不变、缺件、全五星、冷热缓存及API/Web展示，测量新增有界成本。

### 1. 套装组合是求值期输入，不是虚构圣遗物

在 Analyzer 求值上下文中提供仅针对 primary 的临时套装计数覆盖：四件套 `{A:4}`，2＋2 `{A:2,B:2}`。原始 artifacts 对象和属性汇总不修改，第五件继续提供原始属性，但不保留任何旧套装件数或一件套效果。

套装计数通过唯一解析入口传递给所有消费者，包括基础治疗加成和能力判定。所有需要缓存的输入必须包含套装组合身份；原有按 Build 身份复用的含套装结果不能直接跨候选使用。原始词条聚合可以共享，套装派生属性单独解析。需要逐步盘点现有消费者并验证，不能仅改主效果解析后宣称完成。

替代方案：重写五件 setId 虽简单，却会制造虚构装备、受到部位数量影响，并可能被误保存；直接加减效果则漏掉队伍转化，因此均不采用。本功能始终标明“等原始属性、仅替换套装效果”，不承诺库存可实现。缺件配置也保留已有原始属性，并明确“假设凑齐套装，不补主副属性”，不造额外词条。

### 2. Content 预定义同类二件效果与代表搭配

候选来自已维护套装内容，遵循此前确认的套装生效规则和不计入条款，不借此补做新机制。只有1/2/3星的套装不纳入，含四星及五星版本的套装可纳入；四星按等属性理论收益注明限制。支持范围与排除理由保留在内容声明中，前端不展示未纳入四件套的清单，缺失实现仍不能当零收益。

Content 提前声明攻击力、生命值、防御力、元素精通、元素充能效率、分元素伤害等二件效果类别。每类记录稳定ID、类别展示名、效果语义及一对不同真实套装作为计算代表；不在请求时对套装或类别做排列组合，不保留全部真实搭配的展开列表。只生成同类＋同类，如攻击18%＋攻击18%；不生成攻击＋防御等跨类型候选。这是已确认的产品范围，不代表混搭在数学上不可能最优。

分类仍需核对数值、条件、作用对象、来源/叠加等语义，不能只看属性名；不同元素伤害不能合成一类。只有存在两个支持且数据可用的不同真实套装，才允许生成该类别候选；同一套装不得重复获取二件效果，无法证明等价者不能强行入类。类别代表仍通过统一件数覆盖及正式求值链路计算，不另写“直接加属性”的旁路。候选标识按类别而非所有真实搭配生成，候选规则版本同步更新，旧缓存不得复用。

四件套逐套保留身份；不能按角色元素或当前零提升启发式排除，因为套装可能通过间接转化提高指标。

### 3. 复用正式求值和来源重建

Analyzer 增加 `analysis/artifact-comparison.ts` 承载候选构造、枚举和排名；现有 `analysis/analyze.ts` 不继续堆套装逻辑。比较纯函数从包根导出，HTTP 路由只编排。

基线保持当前真实四件、2＋2、散件或缺件配置。每个候选移除 primary 的旧套装来源选择，保留并重新核验队友来源，候选新增效果仍按统一资格、前后台、层数和同名去重解析。候选必要选项以候选身份独立保存，不串用旧套装开关。

只求目标伤害标量；不递归调用完整 analyze，不生成词条收益或其他装备排名。复用现有准备机制，并按依赖边界扩展：基础角色/武器/原始词条可共享，受套装影响的 final stats、增益来源、反应参与者和权重重算。对现有仅有完整轨迹的路径优先保持正确性，再增加同一路径的摘要输出模式，禁止复制伤害公式。

### 4. 排名和增量更新

#### 暴击类四件套的理论调配例外

仅在候选四件套的暴击率效果对当前计算伤害实际生效时，允许折算换套后新增的溢出。用未截断的最终有效暴击率比较：`O0=max(0,CR基准-1)`，`O1=max(0,CR候选-1)`，`Δ=max(0,O1-O0)`；在该候选暴击期望计算中扣除Δ暴击率，增加2Δ暴击伤害。随后仍按正式规则将有效暴击概率限制在0至1。基准的既有溢出不折算，换回相同套装也不产生虚假收益。例如105%→115%只折算10个百分点为20个百分点暴伤；90%→110%同样折算10个百分点；115%→110%不折算。

这是用户确认的理论词条调配，并非套装或游戏本身具有暴击转暴伤机制。原始Build与实际基准不修改；2＋2、无生效暴击率加成的四件套、武器比较、词条边际收益及常规指标均不启用。多事件或多人反应必须针对相同伤害事件的装备者自身有效双暴取值，不将装备者折算扩散到队友贡献，不用面板暴击率替代动作专属暴击率。

复用正式伤害求值链路，在暴击期望求值时局部应用比较专用策略；不复制公式，也不对整个最终伤害乘一个全局补偿系数。响应携带实际折算量；行内注明“已将换套后新增溢出暴击率X%转换为暴击伤害Y%（理论调配）”，无折算时不显示已转换提示。多事件折算量不同时按事件说明，不伪装成全动作统一数值。页面加粗说明旁须注明此例外，避免与“原始属性不变”矛盾。候选规则版本包含本规则，旧缓存不能复用。

服务端维护全候选结果集，返回筛选后的展示列表、总候选数、支持/失败摘要和场景身份。采用 `abs(a-b) <= 1e-9 * max(1, abs(a), abs(b))` 作为初始噪声容限，原始数值排序；按每档最高值为锚比较，避免链式近似相等扩大档位。容限版本属于规则版本。

高于基准的结果全部保留，下方取前两个档位，每档列出全部候选；同类2＋2每类只占一条。这里的完整候选池仅指逐套四件套与维护的同类2＋2，不包含跨类型混搭。等基准不展示。基准零时返回绝对变化、比例为空，前端显示“—”。

必要选项改变时仅求值该候选，但重新筛选完整集合；非指定项跌出榜单时显示短暂“该候选已移出展示范围”，不能凭空消失且无反馈。允许修改默认榜内项及当前用户指定项的必要条件，不增加其他隐藏候选的条件入口。这是对先前仅允许榜内操作规则的已批准扩展。缓存失效时允许重新建立全榜并明确加载，不能用不完整集合挑两个较低档位。单候选失败时其他结果可查看，但明确排名不完整并可重试失败项。

#### 用户指定四件套

提供单选“指定套装”，候选仅为维护池内已支持的四件套；不提供任意2＋2组合编辑，不扩展未支持套装。
默认不选择，选择状态只是当前报告的展示状态，不修改实际装备、持久化配置或伤害计算规则。
服务端保留默认筛选结果不变，另外返回指定候选结果；前端按候选ID去重：榜内只标记、高亮原行，
榜外单独展示标记行。指定项等于基准时也显示，低于第二档时不挤掉默认两档；清除或替换后旧项失去强制显示资格。
条件选项、暴击调配解释均复用已有行组件。指定项改变条件后继续可见，默认排名照常更新。

### 5. HTTP 异步，而非持久任务平台

新增兼容入口，暂定：
- `POST /v1/analysis/core`：原场景请求，返回除装备排名外的现有报告内容及服务端计算身份。
- `POST /v1/analysis/weapons`：完整场景，返回武器列表；继续复用现有单武器更新接口。
- `POST /v1/analysis/artifact-loadouts`：完整场景，返回筛选后的套装比较。
- `POST /v1/analysis/artifact-loadouts/candidate`：完整场景、候选ID和必要选项，更新全榜中该项并返回新筛选结果。

TypeBox 明确各输入输出，不把原 `/v1/analysis` 的必填字段变成可选以实现拆分。旧完整接口保持原默认行为。接口最终命名在实施时可微调，但不能改变兼容策略。

指定功能复用套装列表与单候选接口，增加可选 `selectedCandidateId`，与表示本次改条件对象的
`candidateId` 分离；只允许合法四件套ID。响应补充轻量可选四件套目录与可选指定结果，默认排名
`results` 不混入榜外指定项，失败仍走明确的候选失败信息。省略选择字段保留旧筛选语义。
旧客户端可忽略新增响应字段；候选规则/响应版本升级，旧缓存结果不能冒充新响应。

请求直接等待有界异步批次完成，前端使用普通异步请求；不新增轮询、SSE、SQLite任务表或进程外调度。旧全量流程继续兼容，新页面不调用它做套装排名。

### 6. 可信基准与短期复用

服务端以完整规范化场景、引擎/快照/候选规则版本建立内部身份。规范化必须包含真实前台、效果来源、场景参数、所有Build与条件，不按显示角色名或用户输入基准值缓存。不额外暴露可枚举GET任务查询；每次请求必须提交完整场景，不能只凭其他人的token取结果。访客无需登录。

核心请求保存服务端计算的基准和可复用只读准备，后续两类请求查同一身份；并发miss合并为一个Promise，命中不能重复算基准。浏览器携带身份用于拒绝串场景，不作为可信数值凭据。缓存是有界短期优化而非持久数据源，过期/重启可以重算。绝不写日志中的完整构筑或邀请码。

API 在独立 `services/equipment-comparison.ts` 管理进行中请求、缓存与调度，Analyzer 不依赖HTTP或登录。在进程外无法共用缓存时允许重复计算，不新增分布式基础设施。

指定项ID不进入场景基准身份或候选数值缓存键；候选数值仍由场景、候选ID和必要条件决定。
展示选择应进入响应组装/请求合并身份，避免不同指定项的请求共享错误的选择结果。
切换已缓存指定项只读取并组装结果，不重新求值；修改条件仅使该候选数值失效。
过期时沿用已有可信基准重建与加载流程，不能为展示一个指定项递归生成整份核心报告或武器排名。

### 7. 有界调度与性能门槛

初始可调预算：单进程同一时间只运行一个候选批次，队列最多16个不同计算任务；单任务总时限60秒；批次最多4个候选且累计执行约20ms后让出事件循环，单个候选不可抢占。完成缓存TTL 120秒，最多32个场景且估算载荷最多32MiB；先触及任何上限就淘汰。参数集中配置，实测后可收紧，不以无限调大上限解决超时。

武器与套装任务轮转，重复请求只占一个任务。一个等待者离开不取消其他等待者共用的任务；无等待者时取消尚未运行的批次。容量满返回429，任务超时返回可重试503，输入非法返回400。已有旧全量同步接口是兼容边界，本轮负载验收针对新流程，不能宣称它自动获得全部调度能力。

先记录当前部署规模和本机基线，验收至少覆盖普通直伤、月反应、多人星扩散，冷/热缓存与1/4个并发场景。固定同机同快照，分别记录核心延迟、候选去重前后数量、总耗时、p50/p95、基准及候选求值次数、缓存命中、内存和健康探测延迟。

硬门槛：无改动场景每个有效缓存周期基准求值一次；完整套装任务每个规范候选仅求值一次；单项修改仅新增一个候选求值；异步/同步参考数值一致；资源不越预算。核心路径不得执行装备候选；与“同报告但无装备排名”的基线相比核心p95增长不超过10%。负载测试中健康探测p95目标200ms，若不达标应调查单候选阻塞而非仅更换loading文案。总排名耗时实测公布，未经证据不承诺固定秒数；发现单候选已不可接受时停下来报告，不擅自引入线程池。

### 8. Web 组织

保留现有武器一行一个和短选项布局；新增独立套装报告组件及请求hook，放在武器区域后方。主报告完成后立即渲染，两个区域自动发起请求并各自转圈。场景切换Abort旧请求并检查响应身份；只改候选选项不重跑主报告。套装列表包含当前实际配置基准、四件/2＋2说明及结果档位；2＋2以“攻击力＋攻击力”等类别名显示，不展开真实套装组合。加粗“保持现有主副属性不变，仅替换套装效果”，另说明四件方案含二件与四件效果、2＋2方案含两份二件效果。移除“未纳入完整四件套比较的套装”清单；候选计算失败时的排名不完整警告仍保留。数量称为比较方案数，不暗示游戏有同等数量的套装。辅助指标页面不请求这两类新增套装计算。

## Risks / Trade-offs

- [指定项与默认榜单重复或串响应] → 按候选ID合并显示；选择状态与计算身份分离，快速改选、清除或换场景时以最新请求身份为准。选择失败不清空其他区域。

- [套装计数覆盖漏掉消费者] → 先盘点，覆盖基础治疗、能力、原始来源和多人反应；用手动等价换套差分验证，不能只测输出非零。
- [2＋2错误合并] → 预定义类别、不同真实代表套装限制及效果语义验证，不因属性同名而合并不同条件或数值。
- [缓存制造陈旧面板] → 仅共享无依赖变化的基础项；版本身份及场景全字段，测试冷/热与有/无缓存相等。
- [异步仍阻塞进程] → 有界批次、队列和探测延迟；不夸大单线程的可抢占能力。
- [候选排名被截断或失败掩盖] → 全集合计算后筛选；保留失败状态，不能声称完整。
- [四星/缺件比较不现实] → 显式理论等属性提示，禁止将临时组合自动保存成实际装备。

## Migration Plan

先落契约和计算集成，再落新兼容接口，最后切换Web加载方式。旧接口和配置格式保留，不需要数据迁移。通过集中功能开关可使Web恢复旧武器加载并隐藏套装比较；清空短期缓存即可回滚，不触碰用户数据。发布、部署与OpenSpec归档需用户另行授权。
