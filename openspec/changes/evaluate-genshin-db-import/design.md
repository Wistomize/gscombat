## Context

参见 proposal.md。当前快照 schema v2 的规范身份及 Content 参数引用不能随上游键名改变。初查发现 genshin-db 的参数可能跳号：克洛琳德普攻第五段为 `combat1.param10`，现库对应 `auto[7]`；直接减一会读错值。

依据 [ADR-0003](../../../docs/adr/0003-declare-semantic-actions-against-the-pinned-snapshot.md)、[ADR-0010](../../../docs/adr/0010-require-reviewed-term-evidence-for-multi-scaling-actions.md) 保留显式语义证据。此阶段不采纳正式换源决策，不新增生产架构 ADR；后续切换必须另行记录来源组成与兼容承诺。

## Goals / Non-Goals

- Goals：可重复取得固定输入，生成可检查的候选数值库，量化覆盖、差异和阻塞原因。
- Non-Goals：不让候选产物被正式服务自动发现，不改默认快照、公开 manifest 类型、Content 机制或计算公式；不把上游仓库的总条数等同于可玩角色数。

## Decisions

### 1. 独立的离线工具边界

导入、规范化和比较实现放在 `packages/game-data/tools` 的独立目录，测试使用该包现有测试配置。运行时 `src` 不依赖新上游包。开发期审计入口可以读取 Content 公共导出，但 game-data 运行时不得反向依赖 Content/Analyzer。需要计算时只调用既有权威链路，不写第二套公式。

暂不安装完整 genshin-db 到 Web/API；只获取固定版本所需文件。初始候选提交为 `49a6544a6c6ae36089cb42fa591fc46f01de8bcf`，实现时再次验证提交和清单，并计算 SHA-256。下载仅限导入阶段，缓存命中也须校验；本地输入可支持断网重复验证。

### 2. 显式映射而非数组重排推断

映射记录包含规范实体 ID、上游键、技能组、原始 param 键、目标参数身份、标签、提交与审阅状态。数值相等可推荐候选，不能自动证明映射正确；不得按过滤后位置或 `paramN - 1` 批量确认。

旅行者需要分别映射规范角色、性别/元素变体，保留现有引用；未知实体、测试实体及额外技能组不得自动公开。百分数字符串统一转换至现有单位，但不由描述解析效果逻辑。武器精炼参数须映射到当前参数名称，不仅保存数组次序。

### 3. 逐数据域来源与明确缺口

候选来源报告分开列出 genshin-db 数值、中文描述、已验证旧快照圣遗物固定表以及映射版本。保留旧表真实的 7.0 来源，不标作“已验证的 7.1 原始表”。

固定上游的战斗数值数组未包含被动/命座参数；其中文描述另行逐项审计，不能据此断言上游资料缺失，也不默认继承旧库数值。候选库允许作为不完整的研究产物，但报告必须标记不可切换。必要字段缺失不得补零，有数值未映射条目必须计入待审总数。

### 4. 报告和输出隔离

输入为固定来源清单、映射清单、只读基线库；输出到独立且默认被忽略的评估目录，包括 SQLite、JSON 报告与 Markdown 摘要。拒绝覆盖正式 snapshots、sources/current.json 及用户数据库；失败时不留下看似成功的产物。报告可写入基线和候选哈希，已有运行时 manifest 保持不变，来源组成先用独立 sidecar 表达。

差异类别至少为：一致、新增、移除、数值变化、单位变化、映射缺失、语义歧义、固定旧表继承。按实体和字段汇总，提供完整明细；明确分母，不能只报告成功匹配项。覆盖属性/突破/等级曲线、所有天赋等级、精炼及圣遗物主副词条。实际数值变化与映射错位分开，金样和缺口不得为追求绿色而修改。

下载或校验失败属于执行失败；完整报告包含未解决项属于评估完成但兼容检查失败，命令退出码和报告分别表达两者。两次同输入运行比较稳定内容摘要，忽略生成时间。

## Risks / Trade-offs

- 被动/命座描述尚未完成数值语义映射导致候选不可替换 → 如实列出受影响引用，本轮允许得出暂不能换源的结论。
- 同值参数被错误配对 → 结合中文标签与原始路径审阅；重复值不作唯一依据。
- 新旧来源混合掩盖版本 → 仅允许明确列出的圣遗物固定表继承，逐域记录，不做通用 fallback。
- 审计耗时膨胀 → 一次完整表对比，少量关键集成场景；不为每个角色新增重复测试。
- 上游文本不等于授权完整游戏素材 → 更新第三方来源说明，区分仓库 MIT 与游戏资产权利。

## Migration Plan

本轮没有上线迁移。依次完成锁定、映射、候选生成、差异报告、针对性验证；向用户提交覆盖结论和阻塞清单。确认所有生产引用可用并审阅真实数值差异后，再单独规划正式切换、版本展示、来源契约及回滚。评估工具失败或结论不合格不影响当前 7.0 服务。

## 全量映射扩展

逐技能组锁定原始参数键与规范索引。完整等级向量、顺序及中文标签均一致的组可作为批量验证证据；重复数值必须同时满足整组顺序一致和标签定位，不能只靠数值唯一。旅行者男性普攻的 7 个不一致项逐项核实；不匹配者不能自动写入候选。新角色无旧库金样，单独标记来源直属映射并保留全部原始路径。

武器精炼按 R1–R5 的完整序列匹配当前规范参数；遇到相同序列的多个效果必须结合效果模板和当前参数含义选择。复合字符串不拆分为单值。`stats/talents.json` 不含被动/命座数值数组，并不等于上游没有这些资料：固定的中文 talents/constellations 描述文件须单独审查。旧库 `values_json=[]` 是保留组身份而无参数值，字符串组是元数据，两者均不得计为数值缺口。有数值但仅能从描述中看到字面线索的组仍待语义审阅，不由数字重合自动导入；真正无直接描述的组单列。
