## Context

见 [proposal.md](proposal.md)。当前 `getCandidateActiveEffects` 会在每次加入比较默认效果前删除整个互斥组。对于同一个 active 状态同时贡献生命和精通的遗祀玉珑，新增两条默认声明会只留下后一条。

2026-09-10 对实际注册表只读枚举发现 54 把武器有显式选择效果；只有赦罪与赤月之形声明了角色限定比较默认。这不是 54 把都漏算，也不是全部都属于当前四、五星武器比较候选。详细分类见 [audit.md](audit.md)。

## Goals / Non-Goals

**Goals:** 修复比较默认状态的表达与成组应用，并落实用户确认的上一条表格范围，保持完整/增量入口一致。

**Non-Goals:** 不扩展治疗或站场模拟、不把完整审计文档中未列入最终回复的武器自动纳入修改，不改变当前比较候选星级范围。

## Decisions

1. 扩展现有 `weaponComparisonDefault.recipientCharacterIds` 为 `readonly string[] | "all"`。数组语义和赦罪/赤月之形现有声明不变，`"all"` 仅表示任意合法持有者。无元数据仍表示没有比较默认。拒绝复制当前所有法器角色 ID：那会漏掉将来新增角色。
2. Content 仍是默认状态的唯一来源。遗祀玉珑两条效果均声明 `"all"`，保持同一个互斥组和 `active` 变体。Analyzer 不新增武器或角色 ID 特判。
3. 先收集适用默认声明，按互斥组解析唯一默认变体，再一次性替换该组旧选择并加入该变体的所有默认效果；无互斥组的效果独立加入。清理被移除效果的来源映射，保留无关队友效果。相同受益者下若一个组被声明为多个默认变体，作者审计必须报冲突，不能依赖数组顺序。
4. 保留已有比较默认优先级：适用的比较默认状态替换候选同组旧状态，不改变基线，也不回写调用方原始场景。选中与默认相同的状态不得重复累计。
5. 完整列表与单武器入口继续复用候选场景准备，再通过 `evaluateScenario` 求值；不给增量接口另写算法。依赖方向保持 Content 声明 → Analyzer 组合 → API 输出。
6. 沿用 [ADR-0014](../../../docs/adr/0014-use-one-authoritative-scenario-metric-evaluation-path.md) 和 [ADR-0015](../../../docs/adr/0015-generate-content-registries-from-entity-owned-declarations.md)，没有新增架构边界，不另立 ADR。
7. 纯水流华以现有 `final_hp` 和 `finalHpToDamageBonus` 复用生命转增伤底座：清除量为最终生命上限 × 24%，增伤为清除量 / 1000 × 精炼每千点增伤，再受精炼上限约束。不是海渊终曲的 25%，也不将清除量向下截成整千。保留旧手选部分清除 ID 的兼容性，比较默认优先完整清除状态，不能与旧层数叠加。
8. 纯水流华 E 基础增伤、完整清契、浪影阔剑受疗增攻和静谧之曲受疗增伤采用 maximum_reachable，保持与海渊终曲一致。治疗充分是用户给定的建模假设，不由是否有奶妈推断。
9. 比较默认支持明确的反应输出/后台动作条件，条件不满足不选。万国诸海图谱的两层为本次命中前的预存状态，不是当前命中首次触发后的反向增益。那维莱特、莱欧斯利、芙宁娜的限定默认沿用角色范围与动作过滤，不假设其他角色自动发生生命变化。
10. 用户确认后，为奥兹攻击、夜兰玄掷玲珑一轮、欧洛伦超感知雷击、柯莱跃动单跳、温迪暴风之眼单跳声明 `off_field`，表示这些核心指标采用后台输出场景，不表示技能游戏内只能后台触发。普攻、施放初段和未明确的其他动作不猜测后台。沿用既有前后台互斥 Buff 规则。
11. 静水流涌之辉“其他队友生命变化”默认要求实际至少配置一名队友；单人芙宁娜只有自身生命变化默认。万国诸海图谱读取已求值基线的实际反应或动作明确的反应声明，不为判断状态额外求值，不把直伤型特殊反应标签视为已触发元素反应。

## Risks / Trade-offs

- [比较值与未勾选 Buff 的主面板不同] → 除用户明确统一充分治疗的三把武器外，比较有效窗口不回写主面板；遗祀玉珑效果说明写明后台 5 秒/登场不足 10 秒，不声称全程覆盖。
- [其他可选武器有复杂触发条件] → 保持手动，逐项给出建议，不用“可选即自动”替代条件判断。
- [同组多贡献被覆盖或重复] → 用真实遗祀玉珑场景验证精炼 1/5 的两项效果，与显式开启场景一致，并检查重复选择不会叠两份。
- [性能回退] → 只改变候选默认的线性归并，沿用已经发布的增量接口与缓存边界；不新增全列表重算。

## Migration Plan

不迁移配置或 SQLite，不修改 HTTP/TypeBox 契约。实施验证通过后，只有用户另行要求才提交/推送/部署；回退代码即可撤销比较默认变化。
