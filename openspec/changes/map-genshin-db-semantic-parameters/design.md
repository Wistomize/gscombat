## Context

参见 proposal.md。现有固定来源锁含 704 个 genshin-db 7.1 文件；`stats/talents.json` 提供战斗技能数组，而被动与命座主要位于中文描述。离线评估已将 1,366 个未映射旧组分为 620 个空组、14 个非数值元数据组及 732 个有数值组。后者共有 1,893 个数值叶子字段：688 组有直接同名描述，44 组需要跨章节审阅。现有候选库与生产库隔离。

本设计沿用 [ADR-0003](../../../docs/adr/0003-declare-semantic-actions-against-the-pinned-snapshot.md) 和 [ADR-0010](../../../docs/adr/0010-require-reviewed-term-evidence-for-multi-scaling-actions.md) 的显式语义证据原则。只增加离线映射资产与候选生成，不建立新的运行时数据源边界，因此本轮不另立 ADR。

## Goals / Non-Goals

**Goals:**

- 每个数值叶子字段有唯一的规范目标路径、固定 7.1 来源证据、语义、单位和可复算的来源值；覆盖率用 1,893 作固定分母，另报告组数与 Content 引用覆盖。
- 对字面相等、单位换算、跨章节对应和来源/旧库差异使用同一审阅标准；差异只提示复核，不自动取旧值。
- 所有已确认字段进入隔离候选并由既有 Repository 和 Analyzer 链路检验；未确认者使全量完成门禁失败。

**Non-Goals:**

- 不改变生产快照、计算公式、角色技能声明、用户工作空间、公开 API 或网站；候选可计算不等于游戏 7.1 已完整实现。
- 不把 620 个空组、14 个元数据组伪装成 1,893 个数值字段；它们仍需在覆盖报告中单列。
- 不抓取 GO／旧快照作为候选数值来源，也不从文本中的数字匹配自动批准映射。

## Decisions

### 1. 逐字段来源记录与固定分母

在 `packages/game-data` 的离线映射资产中，为每个旧库数值叶子建立目标键（角色、组、嵌套路径）、上游角色键、文件路径、章节、描述位置、语义名称、旧库单位、来源单位、换算规则及审阅证据。描述只引用固定锁中的路径与片段位置/摘要，避免复制整段游戏文案。覆盖检查由只读 7.0 基线重新枚举 1,893 个叶子，要求每个目标恰好有一条记录；多映射、漏映射和路径形状变化一律失败。

方案比较：按组或数字顺序批量映射较快，但重复数字、嵌套字段和跨章节描述无法保证语义。逐叶子记录较大，却能审阅、追溯和定位用户裁决。

### 2. 受控换算，不执行任意表达式

常见单位采用受控、可检验的换算种类（如百分数字面量、整数、来源字段比例、技能能量上限与描述百分比相乘）；罕见规则由工具侧具名解析器实现，并要求输入路径、公式说明及固定来源值的独立核对。解析器输出必须是有限数值，并转换到现有规范库的形状与单位；不得 `eval` 描述文本或在 `normalize` 中散布角色特判。像琴的 20% × 80 = 16 只能在两个来源位置均锁定后确认。

方案比较：通用自然语言解析器无法证明条件、作用对象和单位；直接复制旧值违反用户决定。受控换算和少量显式解析器牺牲自动化速度，换取可验证性。

### 3. 分批审阅与用户裁决

按角色和组分批处理：先枚举与 Content 引用关联的字段，再处理未被当前 Content 使用的字段；优先级不缩小最终 1,893 的范围。每批产出“已确认、来源数值不等于旧值、需用户裁决”三类记录。44 个跨章节组须确定实际章节及每个字段的取值关系；直接描述组也不能仅凭数字重合通过。歧义记录给用户展示固定来源路径、相关短句、目标语义、候选公式及会影响的 Content 引用；得到明确裁决后写入审阅记录并重跑校验。没有可核实的固定来源时保持阻塞，不继承旧值，也不称完成。

### 4. 候选库和验证边界

`normalize` 仅消费已审阅且通过来源校验的映射记录，按旧组身份与嵌套路径写入候选文档。来源描述变化、换算失败、字段遗漏或重复时不生成成功候选。报告区分来源数据差异、映射未完成、Content 语义未实现与其他既有缺口；完成此映射也不自动设置 `productionReady: true`。用 Repository 路径读取所有新增字段，再对关联的既有 Content 指标做少量权威 Analyzer 集成抽样，不写第二套伤害公式。

依赖方向保持：固定上游输入和旧库只由 `packages/game-data` 离线工具读取；`packages/content` 仅被审计，`packages/analyzer` 仅提供已有计算验证。不存在 game-data 运行时对 Content 或 Analyzer 的反向依赖。

## Risks / Trade-offs

- [描述中缺少隐藏数值或存在多种合理解释] → 停在具体字段并请用户确认；无证据不能标“已映射”。
- [旧库值与 7.1 来源不同，可能是版本变化或单位换算] → 同列原值、来源值、公式与证据，不改旧库或测试期望来追绿。
- [数字字面匹配造成假阳性] → 审阅语义名称、对象、条件和单位，禁止该匹配直接导入。
- [单次审阅量大] → 分角色批次、机器校验固定分母与路径，重点做跨域集成而非大量重复角色单测。
- [来源文案版权与漂移] → 仅存短证据定位和哈希；重新取数时验证固定提交、文件哈希及章节内容。

## Migration Plan

没有线上迁移或部署。实施从隔离审阅资产、分批映射到候选库与覆盖报告，始终保留正式 7.0 快照和来源锁不变。发生阻塞或数值争议时仅暂停当前候选批次；回滚即弃用新的离线候选目录，不需要修改生产数据库。正式切换 7.1 必须另开变更并审查其他数据域、Content 机制和版本展示。
