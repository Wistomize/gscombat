## ADDED Requirements

### Requirement: 分析入口必须一致地拒绝非法请求关系

完整伤害、核心报告、武器/套装比较和辅助指标入口 MUST 在触及对应非法配置时，以可识别领域错误拒绝
错属角色的指标、未满足命座门槛、非法前台/受益人、非法动作参数及非法显式效果/装备条件。
API MUST 映射为 HTTP 400。合法请求的公式、来源、期望值、收益和排名 MUST 保持不变。

#### Scenario: 指标所属角色不匹配

- **WHEN** 请求将其他角色的动作或指标用于当前角色
- **THEN** 对应分析入口返回 HTTP 400 和 invalid_metric
- **AND** 不把该错误留到内部计算后返回 500

#### Scenario: 命座门槛不满足

- **WHEN** 当前角色命座低于所选指标所需门槛
- **THEN** 旧完整分析和新核心报告入口均返回 HTTP 400
- **AND** 不因入口不同而出现 400/500 差异

#### Scenario: 用户填写非法动作参数

- **WHEN** 请求填写不在该动作声明范围或联动上限内的参数值
- **THEN** API 返回 HTTP 400 和 invalid_action_parameters
- **AND** 不改变合法参数的默认值或计算方式

### Requirement: 版本冲突必须与计算失败分开

请求游戏数据版本与当前服务版本不一致，或提交的计算标识与完整场景/计算版本不一致时，API MUST 返回
HTTP 409 和明确的版本冲突错误。缓存过期或服务重启本身 MUST NOT 使仍匹配的完整场景失效；
原有重建计算能力继续保留。

#### Scenario: 计算标识与场景不符

- **WHEN** 调用方使用旧 computationId 提交已变化的场景
- **THEN** API 返回 HTTP 409 和 computation_conflict
- **AND** 提示重新计算，不伪造候选结果

#### Scenario: 缓存淘汰但场景匹配

- **WHEN** 场景和版本仍匹配，但原短期缓存已失效
- **THEN** 系统按原流程重建计算
- **AND** 不把纯缓存缺失误报为输入错误或版本冲突

### Requirement: 部分候选失败不改变输入错误和排名完整性语义

用户显式提交未知候选、非法条件组选项时，API MUST 返回 HTTP 400。
合法基准派生的某个套装候选内部求值失败时，系统 MUST 保留既有部分结果协议，以 complete=false 和 failures
标记不完整排名，不伪造零伤害，不将内部生成配置的不合法简单归咎用户。

#### Scenario: 显式套装选项不合法

- **WHEN** 调用方为套装提交不支持的条件组或选项
- **THEN** 请求返回 HTTP 400 和 invalid_artifact_choice
- **AND** 不将非法选择作为普通候选失败继续排名

#### Scenario: 基准合法但候选失败

- **WHEN** 合法基准与合法显式选择在某个内部候选求值中失败
- **THEN** API 保留可用结果，标记 complete=false 并列出失败候选
- **AND** 修复故障后的重试仍可恢复完整排名

### Requirement: 资源限制和取消保持可区分

比较任务容量耗尽 MUST 返回 HTTP 429，预算耗尽或服务关闭 MUST 使用 HTTP 503，不当作计算内部 500。
取消单个等待者 MUST 不影响其他有效等待者；已断开的连接 MUST 不再尝试写入错误体。
连接仍有效且需要表达取消时，保持既有 HTTP 499 取消语义。

#### Scenario: 同一计算只有一名等待者取消

- **WHEN** 两个请求等待同一比较任务，其中一个断开
- **THEN** 另一请求仍可得到正常结果
- **AND** 取消不被当作内部故障，不向已断开连接写入响应

### Requirement: 用户能看到辅助指标失败原因

Web 在辅助指标请求失败时 MUST 展示 API 的可读 message；代理返回非 JSON 或缺少可用 message 时，
SHALL 退回 HTTP 状态提示。不增加自动重试、不清空用户配置或此前合法结果。

#### Scenario: 辅助指标缺少合法受益人

- **WHEN** 辅助请求因受益人关系不合法返回可读输入错误
- **THEN** 页面显示后端说明，而不是仅显示“辅助指标接口返回 HTTP 400”
- **AND** 用户配置保持不变
