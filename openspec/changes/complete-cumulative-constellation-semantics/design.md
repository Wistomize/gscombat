## Context

当前 `additionalDamageEvent` 最初用于装备独立伤害，刻意丢弃父动作的 `actionId`、`attackKind` 与 `talentSlot`。角色 C6 复用该类型后，追加普攻、战技或爆发段无法获得对应增伤、天赋与低命座效果。治疗类型又要求一项非零天赋百分比，因此无法表达纯生命值百分比或固定命座治疗。Catalog 同时缺少 Build 命座约束，导致低命座配置可以选择只在 C6 存在的指标。

本设计沿用唯一权威场景求值链路与实体归属原则，关联 [ADR-0006](../../../docs/adr/0006-declare-damage-as-an-action-relative-event-timeline.md)、[ADR-0012](../../../docs/adr/0012-evaluate-character-metrics-in-explicit-party-context.md) 和 [ADR-0014](../../../docs/adr/0014-use-one-authoritative-scenario-metric-evaluation-path.md)。它扩展既有类型而不建立新架构边界，因此不新增 ADR。

## Goals / Non-Goals

**Goals:**

- 以来源 Build 的实际命座自动启用所有已达到的 C1 至 C6 效果。
- 让角色追加段以自己的技能类别匹配效果，同时保留父动作的触发上下文和稳定事件来源。
- 让同段动态项和命座治疗进入可审计公式，而不是隐藏在角色专用分支。
- 让界面只能选择当前 Build 已解锁的命座专属指标。

**Non-Goals:**

- 不推断未声明的轮转状态或把次数收益换算为单次伤害。
- 不把装备 proc 重新分类为角色技能伤害；没有声明类别的现有装备事件保持原行为。
- 不在通用层写角色 ID 分支。

## Decisions

### 1. 独立追加段显式声明技能身份

角色拥有的独立追加段可选声明 `attackKind` 与 `talentSlot`。Analyzer 在求值该段的二级效果时，以追加段显式声明的两个独立维度构造派生动作上下文；任一未声明维度不得沿用触发动作。父动作 ID 只作为触发来源与轨迹标识，不让 action-ID 专属增益隐式传给新事件。未声明技能身份的装备追加段继续只接收全局和元素兼容效果。

不直接让所有追加段继承父动作类别，因为协同攻击可能由普通攻击触发却被文本定义为战技或爆发伤害；隐式继承会产生另一类错误。

### 2. 命座门槛只来源于 Build

动作内事件、指标和所需同段项可以声明 `minimumSourceConstellation`。被高命座替换而非追加的旧事件还可声明 `maximumSourceConstellation`。求值和 Catalog 投影均比较来源 Build 的 `constellation`；达到更高命座时所有较低门槛继续成立，只有明确声明上限的被替换旧事件会退出。调用方不能通过 Buff 开关伪造或关闭固定命座事实。

公共 Catalog 若仍需为未选 Build 的编辑器列出全量内容，只暴露向后兼容的可选门槛；计算页面使用已选 Build 过滤，API 求值则再次强校验，防止客户端绕过。

### 3. 同段动态项保持公式顺序

同段加算项可以由固定系数、天赋参数、动作场景参数或效果来源最终元素精通的有上限换算共同组成，并可声明最低命座。一个动作内伤害部分的多属性倍率项也可声明经审计的固定系数与最低命座；事件自身倍率必须作用于该段所有已解锁倍率项。它们在基础伤害区相加，随后共同经过该事件对应的反应、增伤、暴击、防御和抗性；若角色文本明确要求某项先乘生命之契或其他动作状态，该项先解析对应场景倍率再相加。最终元素精通换算只生成当前同段项的攻击倍率，不改写增伤区，也不产生独立事件。

不使用 `damageBonus`近似倍率加算，也不把不同乘区相乘后冻结成角色常量。

### 4. 治疗以可组合来源项表达

治疗指标的基础项与额外项均可由来源攻击、生命、防御、精通或固定值组成，并声明命座、受益方条件、上限与持续/单次标签。受益方 Incoming Healing 和来源 Healing Bonus 仍由统一治疗公式处理。纯命座治疗可将命座项作为唯一基础项，不再要求伪造天赋百分比。

对于依赖“本次承受的护盾伤害”或“受益者最大生命值”的治疗，输入必须是显式上下文项；没有该输入时返回明确的待填写条件，不以来源角色生命值替代。

### 5. 系统审计覆盖声明与可达性

完整性审计检查命座范围、事件/指标引用、追加段技能身份与不兼容反应声明。系统测试以代表性角色覆盖：低命座不可达、C6 累积低命座、追加段继承类别、同段动态项以及独立治疗。角色级快照只验证必要的固定系数，不以大量脆弱单元测试替代端到端求值。

### 6. 派生效果读取队伍与动作的已解析终值

需要读取“队伍中元素精通最高角色”的效果使用配置队伍在该效果应用前的已解析最终元素精通快照，随后应用声明的比例与上限；不得退化为效果来源角色自身属性或固定常量。所有按来源最终元素精通换算的队伍精通分享同时读取“分享前”快照，再统一加到受益方，既不允许自身反馈，也不允许两个分享效果相互循环放大；其他伤害、增伤和命座换算读取应用分享后的最终精通。分享结果只加到声明允许的受益角色。

以所选动作暴击为触发条件的追加段可将触发概率声明为动作最终暴击率。Analyzer 在原动作全部适用暴击率效果解析后，将触发概率限制在 `0..100%`；追加段随后以自身技能类别和可暴击声明独立求值，不继承原动作的反应。

## Risks / Trade-offs

- [风险] 追加段重复获得父动作增益 → 只覆盖显式声明的技能身份，并复用现有效果去重与来源选择。
- [风险] Catalog 过滤与服务端求值不一致 → 两侧共用同一最低命座声明，API 保留最终校验。
- [风险] 将频率型 C6 错算为单次倍率 → 迁移审查区分“改变单次值”和“只改变次数/时序”。
- [风险] 治疗上下文膨胀 → 只增加能直接对应角色文本的类型化输入，不引入任意表达式或角色回调。

## Migration Plan

1. 增加可选类型字段与完整性审计，保证旧声明在缺省值下行为不变。
2. 接入追加段类别、事件/指标命座过滤、同段动态项与治疗组合项。
3. 按审计清单迁移角色内容并删去会改变数值的“排除”说明。
4. 运行 Content 注册表、Analyzer 系统测试、API/Web 端到端与全仓门禁。
5. 如需回滚，先回退角色声明，再回退没有调用者的可选能力；旧请求和工作区无需迁移。
