## MODIFIED Requirements

### Requirement: 固定场景中的核心动作结果

系统 MUST 在角色 Build、队伍、敌人、外部 Buff、动作和反应假设全部显式给定的场景中返回所选核心动作的期望结果。结果 MUST 自动包含来源 Build 已达到的全部累计命座效果；系统 MUST 拒绝低于指标最低命座的求值请求。该结果可以聚合动作内部的多个已声明事件，但 MUST NOT 被标记或解释为完整队伍循环 DPS。

#### Scenario: 求值一个已维护的伤害动作

- **WHEN** 调用方提交通过当前场景契约验证的伤害分析请求
- **THEN** 系统返回所选动作的期望结果及其动作内事件结果
- **AND** 结果说明保持“核心动作”边界，不声称闭合切人、能量、冷却、敌人行为或玩家操作循环

#### Scenario: C6 Build 求值命座专属指标

- **WHEN** C6 Build 选择最低 C6 的已维护指标
- **THEN** 系统求值该指标并同时应用适用的 C1 至 C5、固有天赋和技能类别效果
- **AND** 轨迹逐项列出实际参与的来源
- **AND** 只适用于命座追加段的效果同时记录在该事件与结果级效果清单中

#### Scenario: C5 Build 请求 C6 指标

- **WHEN** C5 Build 请求最低 C6 的指标
- **THEN** Catalog 不把它作为当前 Build 的可选指标
- **AND** 服务端直接请求被明确拒绝而不是返回零值或不完整值

#### Scenario: 同段攻击倍率由最终元素精通决定

- **WHEN** 一个累计命座为原有攻击力倍率段追加由效果来源最终元素精通换算且带上限的倍率
- **THEN** 系统先解析该最终元素精通倍率，并与原天赋倍率在基础伤害区相加后共同乘以最终攻击力
- **AND** 系统不得把该项放入增伤区或拆成独立伤害段

### Requirement: 辅助指标保持类型和上下文边界

非伤害辅助指标 MUST 通过类型化指标定义在显式来源与受益方上下文中求值。治疗可由一个或多个来源属性项、固定项、命座条件、上限与受益方修正组成；治疗、属性增益和标量结果 MUST 保留各自单位、条件与公式，不得被强制换算为某个主 C 的伤害收益。

#### Scenario: 求值一个治疗指标

- **WHEN** 调用方选择已维护的治疗指标并提供来源 Build 与受益角色上下文
- **THEN** 系统返回治疗单位的结果、受益角色、条件状态和公式
- **AND** 系统不生成伤害武器排名或虚构的通用评分

#### Scenario: 求值纯命座独立治疗

- **WHEN** 当前 Build 达到命座门槛，且调用方提供该治疗文本所需的受益方上下文
- **THEN** 系统按声明的来源项和上限求值一次治疗
- **AND** 来源治疗加成、受益方受到治疗加成和命座条件在公式轨迹中分别可见
