## Why

架构台账 ARCH-015 已确认：生产 `buildApp` 在未提供密钥和工作区路径时，仍会接受公开的开发默认密钥并退回内存数据库。
这使部署漏配不能及时失败；配置验证发生在游戏库打开之后，还可能遗留已打开资源。

## What Changes

- 生产启动必须显式提供有效会话密钥和文件型工作区路径；拒绝缺失、空白、过短密钥、已知开发/示例密钥及内存工作区。
- 必要密钥和持久化配置先验证，再打开共享资源；初始化或监听失败释放已经成功取得的资源，错误信息不包含密钥。
- 将必要配置解析归到 API 内的小模块，API 和邀请码管理命令复用必要规则，不建立配置框架。
- 开发/测试保留便利默认值；邀请码管理命令继续要求显式配置，不能借开发默认值创建凭据。
- 保持真实密钥原值、邀请码摘要、Cookie 签名、SQLite Schema 和公开 HTTP 响应不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `architecture/public-entrypoints`：增加生产配置拒绝规则和启动失败资源释放约束，保留唯一组合根。

## Impact

- OpenSpec 触发条件：新增安全及启动兼容性规则，不是纯结构重构。
- 受影响工作区只有 `apps/api`；另更新开发、部署说明及问题台账。
- **BREAKING**：依赖生产默认密钥、示例占位值或内存工作区的错误配置将无法启动；开发/测试默认行为不变。
- 现有 Compose 已要求显式密钥并挂载文件路径，无需新增部署变量或改服务拓扑；实施不读取实际生产密钥或用户库。
- 不迁移数据，不轮换密钥，不撤销有效邀请码/会话；上线时必须沿用部署原有密钥及工作区文件。
- 非目标：ARCH-013 错误契约、限流/缓存、HTTPS/CORS、强制登录、通用配置中心、计算逻辑、提交与部署。
