## Context

动机见 [proposal.md](proposal.md)。ARCH-015 的当前实现仍与复审一致：`app.ts` 先打开 GameData，再解析密钥；
长度超过阈值的公开开发值不会被拒绝，工作区缺路径会退回 `:memory:`。管理命令有另一份校验。
Compose 已显式要求密钥并设置 `/data/workspaces.sqlite`，这不是认定线上已使用默认密钥。

沿用 [ADR-0013](../../../docs/adr/0013-use-invite-scoped-sqlite-workspaces.md) 的邀请码工作区与
[ADR-0018](../../../docs/adr/0018-compose-api-from-resource-route-modules.md) 的唯一组合根和显式资源装配。
本项是补足上述约束的失败保护，不新增包边界、存储模型、配置框架或 ADR。

## Goals / Non-Goals

**Goals:**

- 在取得数据库资源前解决凭据与持久化必要配置；无效配置明确失败。
- API、管理命令共用小型规则，保持 API 的开发默认行为和管理命令的严格行为。
- 初始化失败释放已取得资源，监听失败可诊断且返回非零状态。
- 保持合法配置的密钥字节、邀请码摘要、会话、工作区 Schema 与数据不变。

**Non-Goals:**

- 不修 ARCH-013，不统一全服务错误、日志或环境变量，不强制分析登录。
- 不轮换密钥、不迁移数据库、不增加密钥管理服务、配置包或运行时依赖。
- 不改变会话期限、Cookie、反向代理、HTTPS 或任何计算流程。

## Decisions

### 1. 将小型解析器放入现有 API 服务边界

新增 `apps/api/src/services/workspace/config.ts`，只负责工作区路径和会话密钥解析/校验，无数据库副作用。
接收必要调用配置和环境输入，返回确定值；不反向导入 `app.ts`，不新增 `src` 根文件。
`BuildAppOptions` 形状不变，调用参数优先于环境变量；高优先级显式空值直接失败，不以真值回退掩盖错误。
API 在非生产可允许便利回退；管理命令一律使用严格模式，保持其原有显式配置要求。

保留显式提供的有效原值：空白检查不能把实际密钥 trim 后用于签名。
只拒绝已知公开开发值和 `.env.deploy.example` 中现有占位值，不新增脆弱的通用“熵评分”算法。
生产允许明确的绝对或相对文件路径；不自行猜测卷挂载、改写路径或创建上级目录。
拒绝空路径、`:memory:` 和内存/临时配置；不引入新的 SQLite URI 支持。

备选：继续只靠 Compose 校验会漏掉直接运行和嵌入场景；通用配置框架则超出当前问题。

### 2. 先校验，后取得资源，失败按所有权释放

`buildApp` 在创建数据库前执行必要配置解析，保持原同步公开签名。
数据库取得后交给明确的关闭责任；后续构造或路由装配同步失败时，释放已成功取得资源，再重新抛原始原因。
`WorkspaceStore` 若已打开连接但 PRAGMA/Schema 初始化失败，构造器自己关闭该连接。
正常关闭保持既有 `onClose` 责任，不通过重复释放改变错误；清理异常不能吞掉最初的启动错误。
`server.ts` 覆盖初始化和监听失败，监听失败关闭应用，报告不含秘密值的失败原因并返回非零状态。
不引入容器、全局资源注册表或泛化生命周期框架。

### 3. 以少量真实集成覆盖启动矩阵

新增一个 `test/integration/startup.test.ts`：组合验证生产无效配置、合法文件库重启、开发默认和初始化失败。
复用 `workspace-sync.test.ts` 验证原邀请码、会话、revision 隔离不变。
命令行失败与管理命令用隔离子进程、临时文件和实际 SQLite，避免环境变量污染其他测试。
必要的关闭观测可以监视真实类的方法；不建立假数据库、假 API 或逐角色测试矩阵。

### 4. 主要文件变更

| 文件 | 预期变化 |
|---|---|
| `apps/api/src/services/workspace/config.ts`（新增） | 凭据与路径的小型共用解析/校验 |
| `apps/api/src/app.ts` | 前置校验、显式资源取得/失败清理，组合根保持薄且不改路由 |
| `apps/api/src/services/workspace/store.ts` | 构造中途失败时释放自己已打开的连接 |
| `apps/api/src/server.ts` | 初始化/监听失败诊断、清理与非零退出 |
| `apps/api/src/manage-invites.ts` | 复用严格配置，保留原命令和凭据输出协议 |
| `apps/api/test/integration/startup.test.ts`（新增） | 真实启动与持久性集成场景 |
| `docs/development*.md`、`docs/deployment/tencent-cloud*.md` | 开发与生产配置差异、沿用原密钥、生成随机密钥示例 |
| `docs/architecture*.md`、当前架构台账 | 验收后更新已实现边界与 ARCH-015 状态 |

Compose 的变量名及挂载保持不变；结构守卫不放宽，域包、HTTP Schema、Content 和计算测试不改。

## Risks / Trade-offs

- [旧部署漏配会停止启动] → 明确是目标行为，错误指出配置项；保持原密钥/路径，不自动生成新值蒙混启动。
- [改变密钥导致邀请码全部失效] → 不规范化密钥原值、不自动轮换，集成验证原文件重启后邀请码及会话仍有效。
- [测试改全局环境影响别例] → 使用隔离进程或严格恢复的环境切片，不读取部署 `.env`。
- [清理逻辑使组合根膨胀] → 维持现有 120 行守卫，限定少量资源的所有权，不抽象通用框架。
- [路径配置不等于磁盘一定可靠] → 只保证明确选择文件库并失败不回退；挂载、磁盘与备份仍是部署责任。

## Migration Plan

无 Schema 或数据迁移。实施通过后另行等待提交/部署授权。
部署前只检查必要变量是否配置，不打印值；沿用既有密钥与工作区文件，按原部署文档备份。
缺配则修复配置，不通过生成新密钥或切换空库“恢复”。需回滚时回退代码/镜像，保留原 `.env`、用户库和卷。
本项不自动归档其他变更，也不将计划完成标成修复完成。
