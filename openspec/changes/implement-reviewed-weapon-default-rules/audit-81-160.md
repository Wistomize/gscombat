- **#144 已修复，源码复核通过**：初次审计发现硕果钩仅查询 `plunge_access`，漏掉“当前下落指标默认已有一次有效下落”分支。当前 [effects.ts](../../../packages/content/src/weapons/fruitful-hook/effects.ts) 已新增 `plunge-metric.prepared-damage-bonus`，仅给前台下落；原能力门控条款现只给普通/重击，避免双计。保留此段作为发现历史，不再列为未解决计算缺口；此处不把源码复核冒充合法角色全流程验证。
- **#91、92、110、119、128 coverage 已修复，文件复核通过**：海渊明确包含未达上限的完整清契连续转换；纯水删除部分清契兼容声称；烈阳/天空之刃明确分离已排除的独立追加伤害；无垠改为前台默认三层。具体文件见逐行 coverage 链接。

## 共享路径核对与边界

- [weapon-preparation.ts](../../../packages/content/src/combat/weapon-preparation.ts)、[effect-lifecycle.ts](../../../packages/analyzer/src/scenario/effect-lifecycle.ts)、[capabilities.ts](../../../packages/analyzer/src/scenario/capabilities.ts)：核对治疗实际受益者、自疗限定、前后台保留、来源能力、短窗口次数、一次祭礼重置及反应配对。八把治疗/清契/标记武器未因旧手选 ID 绕过真实资格。
- [action-effects.ts](../../../packages/analyzer/src/effects/action-effects.ts)、[weapon-state.ts](../../../packages/analyzer/src/effects/weapon-state.ts)：受益者选择属于固定来源；同名来源先检查资格/受益者，再按实际解析值去重。种识之叶跨两把武器使用相同精炼表，因此最高精炼在此等价于最高实际数值。Millennial 特例不被泛化到其他面板派生 Buff。
- [stat-conversions.ts](../../../packages/analyzer/src/effects/stat-conversions.ts)：海渊/纯水/木棉使用最终候选 HP，逐项连续转换且逐项封顶；ER 先行解析供合法转换。普通 damageBonus 与 specialReactionDamageBonus 是独立通道，同命中加值与 additionalDamageEvent 分开。
- [combat-action-effects.ts](../../../packages/content/src/combat-action-effects.ts)：按实际 action attackKind/talentSlot/effectiveElements 过滤；箭矢使用 damagePart 限定。此处静态审计不重复证明所有角色声明的伤害标签、最终暴击上限或所有比较入口。
- #82 目前仅 E 能力作为 E/Q 默认准备路径；当前合法双手剑角色均可 E，未找到现实漏算反例，不能据此宣布 Q 独立能力路径已覆盖。#83 满层显式声明 burning，当前可烈绽放的火草水组合也满足 burning 配对，因此当前结果符合规则。
- #130 未显式查 E capability，而采用确认记录“默认提前开 E”的自动属性声明；当前合法法器角色均可 E，未找到数值反例。若未来引入禁用 E 的场景，需补门控。
- #112 只验证实时后台十层/前台零。实体未使用 stat_capture 门，不能凭此静态审计宣称“既有合法快照不撤销”场景已端到端验证；#113 已显式阻止前台旧快照倒灌。
- 无直接 effect 的武器不等于不进候选；本段未改候选清单，亦未把 Royal 最新排除扩展到其他三/四/五星武器。比较入口与全部合法角色矩阵仍由主线总体验证覆盖。
