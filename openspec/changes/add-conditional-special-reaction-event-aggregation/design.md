## Context

见 [proposal.md](proposal.md) 的 Why。当前 Content 时间线可为事件声明直接特殊反应，但所有事件都必须引用角色倍率伤害部分；Analyzer 也把动作效果先汇总为一个动作级数值，再复用于各事件。Calculator 已有两套正确且独立的星扩散公式入口：实际星扩散触发/涡流的参与者聚合，以及角色直接造成、视为星扩散伤害的属性倍率公式。缺失的是把二者编排进同一个核心动作，并按命座与事件准确限定效果。

本设计沿用 [ADR-0006](../../../docs/adr/0006-declare-damage-as-an-action-relative-event-timeline.md)、[ADR-0012](../../../docs/adr/0012-evaluate-character-metrics-in-explicit-party-context.md) 和 [ADR-0014](../../../docs/adr/0014-use-one-authoritative-scenario-metric-evaluation-path.md) 的边界，不建立角色专用求值器或第二条 API 链路。它只是扩展既有动作时间线可表达的事件种类和筛选粒度，因此不新增 ADR。

## Goals / Non-Goals

**Goals:**

- 让来源角色 Build 的 `constellation`成为事件与效果是否参与求值的唯一命座事实来源；C6 自然包含 C1。
- 在一个指标内分别求值实际星扩散触发事件、`1000%精通`独立星扩散事件和 C1 `400%精通`独立星扩散事件。
- 只把 C1 `550%精通`放入实际触发反应的后置固定伤害区，并在公式来源中明确标记。
- 保留逐事件结果和合计，供现有分析、反事实重算和前端轨迹共同使用。

**Non-Goals:**

- 不根据技能轮转自动寻找印记、辉映或梦浮状态；所选指标本身代表这些前提已经成立的固定快照。
- 不把动作内顺序扩展成通用循环、元素量或多目标模拟。
- 不新增 C1 专属指标，也不把三个事件压成一个无法审计的总倍率。

## Decisions

### 1. 将实际星扩散作为新的事件变体，而不是伪造角色倍率伤害部分

Content 的动作内事件使用有判别字段的联合类型：既有角色倍率事件保持不变，新增“实际星扩散”事件变体，声明触发或涡流身份以及所需的固定场景信息，但不引用角色伤害倍率。Analyzer 为该事件从当前配置队伍构造参与者快照，并调用 Calculator 已有的实际星扩散参与者聚合公式。

选择这一方案是因为实际星扩散以角色等级基础反应伤害和参与者权重为基础；把它伪造成 `元素精通 × 倍率`会从第一个乘区开始出错。另一方案是为梦见月瑞希写专用求值函数，但会违反唯一权威链路并使武器、词条和等级反事实计算分叉，因此不采用。

### 2. 事件命座门槛由主 Build 自动解析

动作内事件可声明可选的 `minimumSourceConstellation`，取值限制为 1 至 6。编译动作计划时使用指标来源角色 Build 的累计命座筛选事件：未声明者始终保留，声明 C1 者在 C1 至 C6 均保留。调用方不传额外开关，前端也不展示一个容易与角色配置冲突的 C1 Buff 选项。

梦见月瑞希的 `400% × 元素精通`独立事件声明 C1 门槛。`550%`通过效果来源的 C1 门槛启用。二者都由同一 Build 配置动态解析。

另一方案是用 0/1 手填场景参数控制事件次数，但它允许 C0 手动打开 C1、C6 手动关闭已经成立的固定命座语义，因此不采用。

### 3. 效果筛选增加稳定事件标识

效果目标筛选增加可选的动作内事件标识集合。Analyzer 在求值每个事件时，使用动作信息、当前事件标识、最终元素和特殊反应身份共同解析效果。没有事件筛选的现有声明继续按动作级行为应用，保证兼容。

梦见月瑞希 C1 的 `550% × 最终元素精通`声明为 `specialReactionFlatDamageAddition`，来源要求 C1，且同时限定星扩散联动动作与“实际星扩散触发”事件。它在该事件的精通/反应增伤之后、暴击之前加入。事件筛选使其不会进入 `400%`或`1000%`两段独立事件。

另一方案是在事件声明中直接写 `flatDamageAddition`，但该字段无法表达“引用另一个角色配置的最终元素精通并按命座启用”的来源链，也无法在轨迹中复用统一效果来源，因此不采用。

### 4. 一个梦见月瑞希指标表达一个固定联动快照

新增此前已确认但尚未落地的一个梦见月瑞希星扩散伤害指标；“不新增指标”解释为不再为 C1 拆出第二个指标。该指标的固定前提是：梦见月瑞希处于梦浮状态和辉映状态，由她触发的实际星扩散命中目标；若来源为 C1 及以上，该目标同时带有并消耗 C1 印记；随后求值触发后的下一次周期伤害。

事件构成为：

1. 实际星扩散触发反应；C1 及以上时，其 Fpost 增加 `5.5 × 梦见月瑞希最终元素精通`。
2. 廓然梦生在辉映状态下追加的独立星扩散伤害，基础伤害为 `10.0 × 梦见月瑞希最终元素精通`。
3. C1 印记被该次反应消耗后追加的独立星扩散伤害，基础伤害为 `4.0 × 梦见月瑞希最终元素精通`，仅 C1 及以上存在。

第 2、3 段分别经过特殊反应增伤、暴击、抗性和擢升；不得先把倍率合并成 `14.0 × 精通`。最终指标是已启用事件期望伤害之和。内容声明使用固定 7.0 快照中的 `lockedPassive[3] = 10.0`、`constellation1[4] = 4.0`和`constellation1[5] = 5.5`建立审阅证据或等价快照守卫。

### 5. 以向后兼容的事件结果承载实际反应明细

Analyzer 的动作结果继续向每个事件提供稳定标识、标签和 `expectedDamage`。实际星扩散事件额外携带参与者贡献及其公式轨迹；若共享响应契约尚不能表达该明细，只添加可选的判别字段和参与者字段，不改变既有字段的名称、含义或必填性。Web 根据事件类型展示相应轨迹，并使用同一事件数组求和，不自行重算。

这使旧客户端仍可读取动作总值和事件期望值，新客户端则可解释实际反应的参与者与 C1 Fpost 来源。

## Risks / Trade-offs

- [风险] 将 C1 `550%`按动作级效果解析会污染两段独立事件 → 事件 ID 筛选是必需的集成断言，并校验每条轨迹中的效果来源。
- [风险] C0/C1 事件集合不同导致总值缓存或反事实复用错误 → 动作计划必须由每次候选 Build 的命座重新编译，武器、词条和等级比较沿用同一路径。
- [风险] 实际星扩散参与者结果与普通事件响应形状不同 → 使用向后兼容的判别联合和可选明细，旧字段保持稳定。
- [风险] 固定联动快照被误读为完整循环 → 指标标签与说明明确“辉映联动”，轨迹列出触发反应与后续事件，不展示 DPS 或循环时长。
- [取舍] 本指标假设前提成立而不提供额外 Buff 复选框 → 避免用户配置出“选了指标但关闭其定义前提”的无效组合，代价是暂不比较非辉映状态。

## Migration Plan

1. 先增加类型与完整性审计，并使全部既有声明在缺省字段下通过。
2. 接入实际星扩散事件、逐事件效果解析与聚合结果，保持旧事件求值不变。
3. 增加梦见月瑞希声明和端到端分析回归，验证 C0/C1/C6 累积语义与轨迹来源。
4. 如响应需要可选字段，再同步更新契约、API 和 Web 展示，并运行兼容性测试。
5. 回滚时可先移除梦见月瑞希新声明，再撤销未被其他内容使用的可选事件能力；没有持久化数据迁移。
