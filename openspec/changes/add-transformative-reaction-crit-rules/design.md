## Context

见 [proposal.md](proposal.md) 的 Why。当前 Calculator 的普通剧变反应事件只计算等级基础伤害、反应倍率、精通/反应增伤、后置固定伤害与抗性，且把非暴击值直接作为期望值；特殊反应已有独立暴击参数与暴击率封顶逻辑。Content 的动作效果已经能按来源角色、累计命座和剧变反应种类筛选，但尚无只服务于普通剧变反应的双暴目标。

该设计沿用 [ADR-0004](../../../docs/adr/0004-declare-amplifying-reaction-assumptions-per-action.md)、[ADR-0012](../../../docs/adr/0012-evaluate-character-metrics-in-explicit-party-context.md) 和 [ADR-0014](../../../docs/adr/0014-use-one-authoritative-scenario-metric-evaluation-path.md)：角色语义留在 Content，Calculator 只接收角色无关的公式输入，Analyzer 负责把固定场景与效果解析成输入。它是现有反应声明模型的窄扩展，不建立新入口，因此不新增 ADR。

## Goals / Non-Goals

**Goals:**

- 用一条共享求值链支持“某个普通剧变反应被角色效果赋予固定双暴”的规则。
- 保持角色面板普通双暴、特殊反应双暴和普通剧变反应专属双暴三者边界清楚。
- 让队伍内梦见月瑞希 C6 自动作用于本人或队友声明的普通扩散指标，并保留来源轨迹。
- 保证没有匹配效果的全部既有剧变反应逐值兼容。

**Non-Goals:**

- 不修改特殊反应暴击公式，不让普通剧变反应继承角色面板双暴。
- 不推断梦浮的实战持续时间、轮转覆盖率或触发时机。
- 不在 Calculator 或 Analyzer 中写梦见月瑞希角色分支。

## Decisions

### 1. 增加剧变反应专属的两个标量效果目标

Content 增加普通剧变反应暴击率和暴击伤害两个效果目标，继续使用既有来源、命座与 `reactionKinds` 筛选。Analyzer 将所有匹配来源解析成两个非负标量，Calculator 只接收最终数值。梦见月瑞希声明 `swirl` 限定的 0.3 与 1.0，因此不会污染超载、感电、绽放或星扩散。

选择专属目标而非复用全局 `critRate`/`critDamage`，因为“固定 30%/100%”不是给角色面板加双暴，也不应改变普通直伤或特殊反应。另一方案是在梦见月动作上硬编码 C6，但无法让队友扩散获得同一队伍效果，并会产生角色专用求值分支，因此不采用。

### 2. 专属双暴从零开始聚合，不读取角色面板

普通剧变反应的基础反应暴击率与暴击伤害均为零；只有匹配效果才增加数值。最终暴击率限制在 0 至 1，暴击伤害要求为非负数，期望乘数为 `1 + 暴击率 × 暴击伤害`。这与特殊反应的暴击期望约定一致，但输入来源独立。

当前已知普通剧变反应暴击规则分别限定不同反应，不存在同一反应的冲突来源。效果仍按现有加法聚合；若未来出现“覆盖”或互斥规则，再通过显式 exclusivity 或新的组合语义建模，不在本变更猜测。

### 3. 暴击阶段位于后置固定伤害之后、抗性之前

剧变反应的反应基础、精通/反应增伤与后置固定伤害先相加，再乘反应专属暴击期望，最后进入抗性区。轨迹新增独立的反应暴击阶段，显示暴击率、暴击伤害、期望乘数与已应用效果来源。没有反应双暴时可省略该阶段，以保持现有页面简洁和结果兼容。

### 4. 梦浮使用最大可达固定场景语义

梦见月 C6 两项效果声明为来源角色 C6、仅限普通扩散、最大可达自动选中。当前核心动作指标本就表达一个固定战斗快照，而不是完整持续时间模拟；因此当 C6 梦见月在队且选择扩散指标时，场景代表扩散发生在梦浮期间。C0 至 C5 因累计命座门槛自动排除。

## Risks / Trade-offs

- [风险] 误用全局双暴会让扩散继承面板数值 → 使用独立效果目标与独立公式输入，并断言高面板双暴不改变无效果扩散。
- [风险] 新暴击乘区顺序错误会放大或漏掉后置固定伤害 → Calculator 级公式测试和 API 轨迹测试同时锁定顺序。
- [风险] 队友来源效果只对主角色生效或重复生效 → API 集成测试分别以梦见月本人和队友作为指标来源，并对比 C5/C6。
- [取舍] 最大可达模式默认认为梦浮覆盖所选扩散 → 与当前固定指标产品边界一致，但不代表完整循环覆盖率。

## Migration Plan

1. 增加向后兼容的效果目标和零值解析字段，先证明既有 Content 全部通过类型与注册表守卫。
2. 扩展普通剧变反应公式和轨迹；以无效果场景锁定旧结果，以有固定双暴场景锁定新结果。
3. 添加梦见月 C6 声明与 API 队伍集成测试，并检查反事实重算沿用同一效果选择。
4. 回滚时先移除梦见月声明，再移除没有其他消费者的可选效果目标和公式输入；无持久化数据迁移。
