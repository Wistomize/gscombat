## 验证与过程中发现的问题

1. 先新增契约测试：旧 Schema 会把门槛当作未知字段，连非法元数据也不校验；补齐后边界检查通过。
2. API 新集成断言真实 HTTP、覆盖报告、独立的行秋限制与未声明时省略；旧一致性测试曾主动删掉
   `minimumSourceConstellationByValue`，现改为对完整声明比较。这是已批准的契约修复，不是修改伤害数字。
3. Content 两个分组核对全部目录与条件，遍历所有对象验证没有共享嵌套引用，再主动修改代表字段，
   证明源和后续响应不变。Web 复用完整配置/计算流程及既有目录测试，不新增逐角色矩阵。
4. 包导出通过真实 ESM 导入验证，旧根与新子入口使用相同工厂和目录。一次探针使用了 CJS require.resolve，
   不适用于这个原本就仅声明 import 条件的包；改用原有 ESM 方式核对，没有为探针改变包兼容范围。
5. 客户端实际静态依赖图通过；生产 11 个客户端 JS 文件共 1,115,847 字节，未命中检查的 1,544 个
   战斗效果 ID。共享 Schema 字段名不是实体效果声明。本项不宣称做了 JS 性能优化，静态字面量检查
   也不等于证明任意动态拼接路径；没有为避开问题引入生成快照。
