## Context

动机见 [proposal.md](proposal.md)。上一轮已完成单行增量接口、只读 SQLite 查询缓存和多人反应来源/受益方拆分；本次不重做这些功能。

当前代码与短采样证据：

- `listCombatActionEffects()` 每次拼接全部 1,459 条声明；`assertSelectedActiveEffectExclusivity()` 每次重新构造完整 ID Map。
- 来源攻击/防御解析分别扫描同一规则表、构造队伍信息，并重复调用自身装备效果解析；`resolveScenarioActionEffectContext()` 顺序准备生命、攻击、精通和防御来源。
- 雷神国家队完整分析含 1 基准、40 武器、11 词条和 2 成长项，共 54 次求值。2026-09-27 短 CPU 采样中，武器比较调用树约占 71%，互斥检查自身约占 12%，规则列表构造自身约占 5.7%。调用树比例会重叠，不相加；这不是全角色分布或严格耗时基准。
- 当前工作树已经完成武器规则迁移、通过 1,082 项测试但尚未提交；HEAD 仍是旧版本。优化差分必须锁定当前工作树及其固定数据，而不能用 HEAD 旧武器规则作为正确性基准。

## Goals / Non-Goals

**Goals:** 先消除已证明重复的规则/输入准备，再复用同一条件下的来源准备；同时减少完整分析和单行更新的 CPU 工作量，公开数值、轨迹、选项、顺序与错误行为不变。

**Non-Goals:** 不削减比较池或效果资格；不增加线程池、Redis、用户场景长期缓存、通用依赖图引擎或仅为求快而另建数值流水线。不删基准轨迹、不跳过候选合法性验证。

## Decisions

### 1. 分清三层复用，不使用一个全局场景缓存

| 层级 | 可复用内容 | 生命周期/失效边界 |
| --- | --- | --- |
| 固定声明 | 效果列表、ID/来源索引、仅依赖声明的静态分类 | 当前 Content 模块版本；不含角色配置或用户选择 |
| 单次分析的纯输入 | 固定数据身份、不变 Build 的裸属性/圣遗物汇总、队伍成员元素/身份、动作固定元数据 | 当前公开调用；武器/等级/天赋等改变时只复用未变的纯输入，绝不按 buildId 单独缓存 |
| 单个场景变体的动态准备 | 规范化后的选择、来源绑定、同条件的自身装备准备、属性分阶段中间结果 | 当前候选/词条/成长变体及其明确上下文；事件/前后台/阶段不同不得误命中 |

第三层的最终队友属性不跨候选共享：换武器可能改变治疗资格、元素精通分享、充能转换和全队增益。第二层只复用无需场景语义即可确定的输入，例如未换装队友的圣遗物原始汇总，而非“队友没换武器所以最终属性不变”。

### 2. 静态索引优先，保持声明顺序和来源语义

Content 负责实体声明及其固定查询投影，Analyzer 负责场景应用。索引按声明 ID、来源身份与稳定效果类别组织；实际装备、队友、圣遗物及角色来源的并集保留原声明顺序、去重和同名多来源含义。不把按角色/武器选择后的动态资格结果存进全局索引。

先替换热路径中的重复 `flatMap`、`new Map`、静态 `filter`；互斥验证的纯选择检查可以在已规范化的变体中复用，但事件的生效效果互斥仍按实际上下文判断。错误不得因“已经验证基准”而在候选侧跳过。

不向调用者暴露可写的内部 Map/Set。现有返回列表的容器副本语义需要保留，不能为了缓存突然允许调用方排序/追加污染其他请求；热路径使用受控查询而非反复复制全表。避免用 `Object.freeze(Map)` 误当作禁止 `.set()` 的保护。

备选：只缓存列表但继续重复建立全量 Map，会留下主要热点；给每个武器加局部快捷分支，则违反实体声明和统一解释器边界。

### 3. 请求内准备上下文是私有实现，不改变公开接口

在 Analyzer 现有场景/求值层加入最小的私有准备对象，沿正式调用链显式传递；不用模块全局“当前请求”，也不向 HTTP 接受预计算结果。完整分析与单候选入口分别创建自己的上下文；公开单指标/辅助入口没有共享调用者时自行创建。

首先统一请求内成员输入准备，再让 HP/ATK/DEF/EM 解析器消费同一变体已经算好的相同前置结果。复用资格要涵盖真实动作/来源/受益者、前后台及快照身份、规范化效果和来源绑定、武器选择、充能基础、词条干预接收者、敌人数与计算阶段等实际依赖；参数不同就重算。优先显式准备槽位/阶段记录，不采用每次序列化整个场景的万能缓存键。

保留当前“精通分享前→分享后”“充能→薙草/绝缘”“来源最终属性转换”等有序阶段，不能为凑同一次遍历而把所有效果提前合并。相同函数名不代表相同阶段输入。多角色反应贡献仍用真实前台和来源身份；箭矢/附加事件/逐击消耗效果不共享不适用的事件结果。

每个候选产生独立动态准备对象，上一候选不能写入下一候选；公开调用返回后不保留用户场景。私有上下文对固定数据仓库实例绑定，跨库调用创建新上下文。既有有界 GameData 缓存继续使用，不增加第二套数据库缓存。

备选：跨候选缓存最终面板虽可能更快，却需要完整依赖失效模型，且容易重现队伍 Buff 串用；本次不采用。仅把同步计算包装成 Promise 不减少工作，也不采用。

### 4. 先按热点验证，再逐层复用，不追求一次性重写

实施顺序为静态索引→纯输入准备→同变体来源准备。每层都独立与优化前基线做差分并重新采样，确认调用量下降；没有命中或没有收益的缓存不保留。当前采样未证明轨迹构造是主要瓶颈，本轮不引入数值专用模式，也不削减公开轨迹。

以少量真实集成场景覆盖普通直伤、梦见月风/冰反应、改变全队效果的武器、前后台与来源同名选择、薙草/绝缘、辅助来源属性和多事件消耗。复用现有场景，不为每个角色重新复制公式测试。结果比较包括基准、全部候选、词条/成长收益、事件与来源轨迹及合法选项，而非仅最终总伤害。

计时与 profiler 分开，固定 Node/数据/场景/构建，在无测试并发时预热并交替采样各 3 次。报告中位数、候选数、热点调用数和缓存大小；不把时间写成脆弱 CI 门槛，也不提前承诺固定倍数。若完整分析变快但单行或多人反应退化，必须定位而不能只挑最好场景交付。

### 5. 维持现有架构约束

依赖仍为 API → Analyzer → Content/GameData/Calculator。主要生产变更在 Content 与 Analyzer，实体规则、Calculator 公式、公开 Contracts 和 Web 流程保持原样。

延续 [ADR-0014](../../../docs/adr/0014-use-one-authoritative-scenario-metric-evaluation-path.md) 与 [ADR-0021](../../../docs/adr/0021-use-stateless-incremental-weapon-comparison.md)；本次是其无状态和同变体复用边界的细化，实施时补充 ADR-0021，不另造冲突决策。`skip_specs: true`：不新增可观察行为要求。

## Risks / Trade-offs

- [误复用导致 Buff/前后台串用] → 变体及来源/受益/阶段显式隔离，以不同武器、条件交替 A→B→A 和重复 buildId 的独立请求验证。
- [共享容器被修改] → 内部索引不暴露写入口；保留公开容器行为，验证调用者修改结果不污染后续计算。
- [静态索引漏声明或打乱顺序] → 与旧列表逐项比对所有 ID/顺序，保留旧兼容选择和同名多来源用例。
- [新增准备结构反而变重] → 不建立通用缓存框架；记录创建次数、命中范围及耗时，无实际收益则撤回该层实现。
- [已有脏工作树导致基线错误] → 保存当前源码/构建身份和输入哈希，差分隔离目录不切换/清理工作树，不用旧 HEAD 替代。

## Migration Plan

无需存储迁移、数据更新或 API 版本升级。优化前后仅允许耗时/内部调用次数变化；若发生公开数值或错误差异，视为回归并先定位。各层保持可独立回退的局部修改，不用生产开关维护双求值链。提交、推送、部署及 OpenSpec 归档等待用户另行授权。
