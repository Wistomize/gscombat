## Context

参见 [proposal.md](./proposal.md) 的动机。海渊终曲当前有两个可选效果：施放元素战技后的攻击力百分比，以及直接写死为精炼上限的平面攻击力；其覆盖文件另保留一个“部分或未达上限清除”的 `unsupported` 分支。发布层要求装备的全部覆盖分支均为可发布状态，因此海渊终曲没有进入公开目录，Analyzer 的武器比较也不会遍历到它。

现有权威链路已经支持以效果来源 Build 的最终生命值为输入、乘以精炼表并保留每项精炼上限，无需新增公共类型、计算阶段或角色特判。实现探针发现，延迟的最终生命值转平面攻击路径此前只汇总乘数，尚未在最终换算和轨迹物化时应用已保留的单项上限；本变更需要补齐这条通用既有语义。武器替换后，Analyzer 会为候选 Build 重新解析最终属性，能够保证生命值来源与同场景比较一致。

## Goals / Non-Goals

**Goals:**

- 使用海渊终曲装备者在候选场景中的最终生命值，动态计算完整清除生命之契后的平面攻击力。
- 在默认可达满效果模式下自动应用海渊终曲的两段可达效果，并使其进入所有兼容单手剑角色的武器比较。
- 保持公式来源可解释，使效果标签能看出“25% 生命之契完整清除、按精炼系数换算并封顶”的组成。
- 复用现有 Content 声明与 Analyzer 求值链路，不创建海渊终曲专用分析分支。

**Non-Goals:**

- 不模拟治疗行为、生命之契持续时间、叠加过程或清除失败。
- 不接受用户输入的任意生命之契清除比例，也不输出部分清除档位。
- 不改变其他生命之契装备、角色效果或公共请求与响应契约。

## Decisions

### 1. 复用最终生命值派生且带上限的效果值

海渊终曲平面攻击效果使用现有最终生命值派生表达：精炼 1 至 5 的有效生命值乘数为 `[0.006, 0.0075, 0.009, 0.0105, 0.012]`，分别等于 `25% × [2.4%, 3.0%, 3.6%, 4.2%, 4.8%]`；上限继续使用 `[150, 188, 225, 263, 300]`。效果仍进入平面攻击力属性区，来源 Build 为当前武器装备者。

延迟换算阶段按每条已应用效果分别计算 `min(最终生命值 × 乘数, 单项上限)` 后求和，并在 UI 轨迹物化时使用相同封顶规则。没有上限的磐岩结绿、护摩之杖等既有转换保持原结果。这样可以直接得到 `min(最终生命值 × 25% × 清除系数, 精炼上限)`，并避免新增只服务于一种武器的中间“生命之契值”领域对象或公共响应字段。效果标签与测试保留 25% 和清除系数的分解，以免有效乘数折叠后丢失解释。

备选方案是新增通用的多级乘数组合类型并在轨迹中创建“生命之契生成量”中间节点。当前没有第二个已确认需求，新增类型会扩大 Content、Analyzer 和轨迹契约，故不采用。

### 2. 将完整清除状态声明为可达满效果

施放元素战技后的攻击力百分比和平面攻击力都声明为 `maximum_reachable`，不再作为必须手动选择的可选效果。武器比较替换为海渊终曲后，既有最大可达效果选择器会自动纳入两项效果，无需维护按角色枚举的武器对比默认列表。

这符合网站当前“武器与圣遗物效果默认吃满”的统一语义。手动效果模式不会自动假定该状态；本变更不新增额外 Buff 复选框。

备选方案是继续保留 `active` 并为每个单手剑角色维护对比默认名单。该方案会产生角色枚举维护负担，并容易遗漏未来角色，故不采用。

### 3. 将部分清除分支标记为当前分析边界外

覆盖说明明确记录：当前产品固定采用治疗充足且完整清除的可达状态，任意部分清除不属于受支持输入，因此该分支应作为已审阅但不适用于当前模型的状态，而不是阻断整把武器发布的未知能力。海渊终曲由实体自身的 Content 目录维护，中央目录继续只消费生成注册表。

备选方案是放宽所有装备的发布规则，只要任一分支完成就发布。该方案会让真正缺失伤害相关分支的装备泄漏到用户界面，影响范围远超本问题，故不采用。

### 4. 保持现有依赖方向与公共契约

静态精炼常量和效果语义继续归属 `packages/content`；`packages/analyzer` 只使用通用最终属性求值和同场景反事实流程。`apps/api` 与 `apps/web` 无需增加字段或定制逻辑，只会观察到目录新增武器以及分析结果中新增候选项。

该决定沿用现有单一权威场景链路，不形成新的长期架构边界，因此无需新增 ADR。

## Risks / Trade-offs

- [玩家实战治疗不足，无法完整清除生命之契] → 页面按既定可达满状态计算，效果标签和覆盖说明明确该假设，不把结果描述为任意实战时点。
- [将两个系数折叠为有效生命值乘数后解释性下降] → 在实体常量命名、效果标签和聚焦测试中同时保留 25% 生命之契比例、清除系数和封顶值。
- [最终生命值解析顺序错误导致候选场景沿用原武器属性] → 集成测试使用两个不同最终生命值 Build 验证非封顶值随候选 Build 改变，并验证武器比较返回海渊终曲。
- [覆盖状态放宽意外发布不完整武器] → 只调整海渊终曲实体的已审阅分支，不修改全局发布判定。

## Migration Plan

1. 先更新实体声明与聚焦测试，再刷新生成注册表检查。
2. 验证 Content 目录发布海渊终曲，并验证 Analyzer 在同一场景中按最终生命值重算武器收益。
3. 通过工作区构建后再部署；无需数据迁移或 SQLite 变更。
4. 若发现回归，可回退海渊终曲的效果与覆盖声明，目录会恢复为不发布状态，公共数据结构不受影响。
