# 圣遗物前后台与持续语义全量审查

日期：2026-09-11。范围：当前 inventory 的 **63 套**，包括一件套、低星套装、治疗/护盾规则；不是仅扫描伤害注册表。

实施时请以 [用户确认后的实施分类对账](implementation-inventory.md)、design.md 和 tasks.md 为准。本文件保留最初问题调查；其中站位、手选和持续策略的建议已被后续逐套确认部分取代，不能直接当作当前规则。

## 证据与结论边界

- 逐套检查 `packages/content/src/artifacts/<目录>/{effects,coverage}.ts` 的效果、条件、受益范围及排除原因；伤害注册表之外补查 `rules/equipment/healing/effects.ts` 和 `rules/equipment/recipient/effects.ts`。
- 游戏描述与本项目 7.0 固定上游提交 `98aafa1f135f086524b611c7d5b5bfb78d98bb6d` 的[中文圣遗物文件目录](https://github.com/frzyc/genshin-optimizer/tree/98aafa1f135f086524b611c7d5b5bfb78d98bb6d/libs/gi/dm-localization/assets/locales/chs)对照：每套对应 `artifact_<inventory ID>_gen.json`。全部 63 套描述已读取；批量请求中磐岩首次超时，后单独读取成功。没有修改数据快照。
- 描述未写清的后台触发实测补查 [KQM TCL 原始机制测试汇总](https://library.keqingmains.com/equipment/artifacts)：逐影后台不新增层数但保留已有层数；教官和翠绿减抗要求来源在前台触发；染血后台击杀不能触发。对未核实条款不按“文案没写后台”自动推断。
- 当前所有 artifact CombatActionEffect 声明均未使用已有 `requiresSourceOnField` / `requiresRecipientOnField`。`effect-selection.ts` 的最大可达选择按效果条件和互斥组挑选；这不等价于具备完整触发/持续证明。
- 本文的“缺口”指代码可见的遗漏或表达缺失，**不是已用玩家配置逐套复现**，也不是宣称所有套装数值都错误。状态型条款的旧“已触发”快照仍有价值，需要类型化约束而不是删除。

## 验收原则

全量清单覆盖不等于全量机制已复现。实施必须把“需核证据”的条款补到声明旁；证据不足时保留受约束的显式准备状态并提示假设，不允许后台自动刷新。验收以几组跨套装的集成场景覆盖不同规则，不为每套复制单元测试。
