## Goals / Non-Goals

**Goals:**

- 所有已支持圣遗物条款有可审计的站位分类；相同规则只实现一次。
- 标准准备场景保持少输入；仅用户指定条款增加选择，默认假设在来源轨迹可见。
- 普通伤害、特殊反应多人贡献、属性转换、辅助指标与武器比较一致。

**Non-Goals:**

- 不提供任意逻辑脚本 DSL，不模拟整队时间线、逐秒叠层或治疗累计；魔女与苍白仅根据技能能力和有效配置派生固定窗口内的施放/合法命中机会。
- 不把所有“施放后”改成当前前台条件；不把后台指标变成新角色配置版本。

## Decisions

### 1. 四种职责分别声明

拟在现有 Content effect 类型上复用小型结构，最终名字以实现可读性为准：

| 维度 | 内容 | 示例 |
|---|---|---|
| trigger | 事件种类、来源当时的 on_field/off_field/any、必要状态及证据 | 教官来源前台反应；绘卷来源触发时夜魂 |
| applicability | 当前来源站位、当前受益者站位、现有动作/元素过滤 | 黑曜二件当前前台；昔时的受益者必须前台 |
| retention | 常驻、持续状态、退场清除；具体简化口径逐项确认 | 宗室持续；辰砂退场清除；剧团额外部分仅后台 |
| recipient | 现有 self/队伍/敌方/辅助接受者关系，必要的元素选择器 | 天之美赐按来源及实际前台元素给全队 |

使用小型可辨识类型区分必要条件；常驻条款明确 always，不要求几十条冗余字段。原始持续时间作为机制依据保留，不生成计时器、宽限窗口输入或事件历史。现有 source/targetFilter 保留职责，不再造一套冲突的目标选择字段。

天之美赐需要的通用选择器为“来源元素”“当前前台元素”及二者去重并集。只选择增伤元素，不把全队受益误缩为前台受益。课业统一按角色机制资格判断：拥有该机制则默认已完成，不读取或新增账号任务完成状态；无此机制的角色不具备资格。沿用已有角色资格元数据，不因名称标签或队友具备资格而授予来源资格。

天之美赐默认策略（用户已确认）：合格装备者默认已施放 E，来源前后台均可触发；无魔导·秘仪时只给来源元素 20%，有魔导·秘仪时给来源与实际前台元素各 40%，同元素去重且不追加原 20%。后台受益者也可获得对应元素加成，切换计算贡献者不得改变元素集合；二件套 20% 充能始终保留。无需额外 Buff 或时间输入。机制依据为固定快照 [CelestialGift](https://github.com/frzyc/genshin-optimizer/blob/98aafa1f135f086524b611c7d5b5bfb78d98bb6d/libs/gi/dm-localization/assets/locales/chs/artifact_CelestialGift_gen.json)，原始持续 20 秒不转化为时间推演。

### 2. 角色声明、队伍派生、效果查询

依赖 [ADR-0022](../../../docs/adr/0022-preserve-scenario-field-identity.md)。当前身份不得随贡献者求值改变；来源、指标角色、实际前台、辅助受益者使用不同 ID。

新增三个小型共享模块，其余接入已有文件；生命周期求值单独放在 scenario，避免继续扩大 action-effects.ts，并供后续辅助入口复用：

```text
packages/content/src/
  combat/capabilities.ts        能力类型、作用对象与条件
  combat/types.ts               CharacterCombatCoverage 挂接声明
  characters/<角色>/combat.ts   角色自身能力及技能来源
  artifacts/<套装>/effects.ts   查询所需能力，不判断角色名字
packages/analyzer/src/
  core/field-presence.ts        沿用唯一前台身份
  scenario/capabilities.ts      按配置与场景派生有效能力来源
  scenario/effect-lifecycle.ts  来源/受益者站位、准备与保留规则
  effects/action-effects.ts     沿用效果资格入口
```

最小能力包含回血或主动扣血、作用对象（自身/当前前台/全队）、来源前后台资格、命座/技能状态等必要条件，以及可追溯的技能来源 ID。角色声明留在已有 combat.ts，通过现有生成注册表收集，不增加每角色微型文件或中央手写名单。

Analyzer 提供类似 `findCapabilityProviders({ kind: "hp_loss", recipientBuildId })` 的查询，返回满足条件的来源及依据，不仅是布尔值。派生结果随实际配置和 FieldContext 变化，不存入 Build/数据库，也不让用户手填角色固有能力。纯队伍组成状态仍归现有 team-state；需要站位的能力解析保持独立。

自身扣血只作用于来源自身，全队扣血才可能让其他成员满足条件；来源的命座、形态和有效状态必须满足。主动扣血不等于受到攻击，拥有治疗能力不证明实际治疗量或累计次数。现有 after_primary_burst 是动作准备状态，不与角色能力塞入同一枚举。默认满层由套装已确认策略决定，能力查询仅提供资格证据。

不新增登场秒数、事件列表或准备时长输入；仅经用户确认的 Buff 选择复用现有场景条件。今后其他实体可复用能力形状，本轮不借此全面重写武器。

### 3. 最大可达仍然受规则约束

每类条款采用用户确认的默认准备策略：常驻、当前站位限定、符合资格的充分准备或明确手动选择。默认规则而非自由求极大值。后续未确认的条件效果如未明确允许后台，按前台限定提出方案，不因其检查敌人状态而自动允许后台；已有逐套确认的常驻、后台和退场保留口径不批量改动。

冰风迷途的勇士（用户已确认）：撤回前后台均可用及要求实际冰附着的建议。四件必须装备者处于真实前台，队伍含冰元素角色（包含自身、排除空位）即默认自身暴击率 +20%，不要求挂冰能力、敌人实际冰附着或装备者为冰元素。冻结在外部“敌人与 Buff”场景提供独立开关，默认不开启，不因水冰组成自动判为冻结；沿用现有冻结字段与入口，不能新增第二份套装冻结状态。前台且队伍有冰时，冻结开启额外 +20%，四件合计 +40%；无队伍冰元素不满足本套基础资格，外部冻结选择也不绕过本套资格或后台限制。该外部状态可供既有冻结消费者按各自规则读取，整次分析及候选比较保持一致；队伍有冰的本套准备假设则不写入全局敌人冰附着。二件 15% 冰伤前后台保留，只进入普通冰伤增伤区；四件条件暴击仅装备者受益，不限伤害元素，按既有暴击适用范围计算且有效暴击率封顶 100%，不将无法暴击的伤害变为可暴击。旧四件选择不能绕过自动条件，缓存包含外部冻结开关与实际队伍/站位；不引入时间模拟或全局敌人模拟。来源标记“队伍有冰，按默认策略计入”及“目标冻结”的各 20%，区分用户简化与原始机制。依据固定快照 [BlizzardStrayer](https://github.com/frzyc/genshin-optimizer/blob/98aafa1f135f086524b611c7d5b5bfb78d98bb6d/libs/gi/dm-localization/assets/locales/chs/artifact_BlizzardStrayer_gen.json)。

武人（用户已确认）：有四星版本，属于本轮维护范围。前台默认装备者已经施放 E，不要求 E 命中；四件提供自身 25% 普攻/重击增伤，二件另计 15%，合计 40%。后台四件不计，二件 15% 保留。两部分均不限伤害元素，按事件伤害类别匹配，不加成下落、E/Q 或不接受普通增伤的特殊反应。复用沉沦的施放准备与站位规则，不复制实体专用解析或引入追忆的元素能量支付条件。无开关或八秒计时，旧触发选择可解析但不绕过站位；当前伤害、多人贡献与候选/增量对比保留真实 FieldContext 和相同准备假设。该后台口径为工具简化，不改写原始持续机制。固定描述依据：[MartialArtist](https://github.com/frzyc/genshin-optimizer/blob/98aafa1f135f086524b611c7d5b5bfb78d98bb6d/libs/gi/dm-localization/assets/locales/chs/artifact_MartialArtist_gen.json)。

被怜爱的少女（用户已确认）：默认装备者已施放 E 或 Q 完成四件准备，不要求命中或技能本身能够治疗。全队角色获得 20% 受治疗效果加成，来源退场仍保留，接受者前后台均可受益，不把切换治疗指标对象等同于切换前台。二件套仅为装备者自身提供 15% 治疗输出加成；现有治疗公式分别读取实际治疗者的治疗加成及接受者的受治疗加成，不把二件分享全队、不给每个角色虚增 35% 治疗输出，也不在既有公式外重复乘一份系数。四件本身不产生治疗、伤害、护盾或攻击力，不因穿套就把非治疗角色声明为可回血，也不证明累计治疗量；不扩展海染/昔时累计机制。沿用现有 healing/recipient 语义接入实体效果和统一来源，保留同名效果既有去重规则；不新增开关或十秒计时，来源解释默认预施放。完整分析、辅助指标与候选计算共享同一来源身份和准备状态。固定描述依据：[MaidenBeloved](https://github.com/frzyc/genshin-optimizer/blob/98aafa1f135f086524b611c7d5b5bfb78d98bb6d/libs/gi/dm-localization/assets/locales/chs/artifact_MaidenBeloved_gen.json)。

来歆余响（用户已确认）：前台普通攻击用长期平均触发率近似单次期望，不再手选本次触发，不按最大可达保证幽谷祝祀。每次触发后重置为 36%，连续失败的后续概率为 56%、76%、96%、100%；平均判定数 E[N] = 1 + 0.64 + 0.64×0.44 + 0.64×0.44×0.24 + 0.64×0.44×0.24×0.04 = 1.99188736，故 p = 1/E[N] ≈ 0.502036420372686。基础伤害加算系数为 0.7p ≈ 0.3514254942608802，乘最终攻击力后作为同次普攻基础区加算，继续接受适用的增伤、暴击、防御与抗性，不写成普通增伤百分比，也不重复叠加原 0.7 系数。内部使用完整精度，展示约 50.2% 触发率、35.14% 攻击力系数和平均假设。后台四件不计，二件 18% 攻击前后台保留；只匹配普通攻击伤害，不加成重击、下落、E/Q 或不适用的特殊反应。每次有效判定仅加成一次普攻命中是明确近似；不模拟 0.2 秒判定间隔、多段共享 0.05 秒增益、网络延迟或随机事件，不将该长期均值当成首次命中的 36% 概率，也不承诺所有攻击频率下都精确。此固定期望系数不构成通用概率模拟器。沿用现有同击加算入口与真实 FieldContext，旧触发选择可解析但不覆盖平均策略或后台限制；候选和增量比较统一取值。audit 中保留显式触发选择的早期建议由此决定取代。固定描述依据：[EchoesOfAnOffering](https://github.com/frzyc/genshin-optimizer/blob/98aafa1f135f086524b611c7d5b5bfb78d98bb6d/libs/gi/dm-localization/assets/locales/chs/artifact_EchoesOfAnOffering_gen.json)。

逆飞的流星（用户已确认）：前台装备者在当前队伍与配置中有可保护自己的有效护盾来源时，默认受盾，四件提供自身 40% 普攻/重击增伤。来源须按实际技能、命座、状态和受益范围判断；队友只能给自己提供的盾不使装备者合格。具备普通结晶反应条件时默认拾取晶片获得保护，月结晶/月笼本身不提供该资格；被月结晶替代的水结晶不能再作为普通水晶片来源，其他仍合法的普通结晶不受误删。不借夜话或其他套装的准备假设冒充护盾来源。后台四件不计，不新增开关、不模拟护盾耐久、破盾或持续时间；这是工具默认策略，不宣称模拟了实际盾覆盖。二件 35% 护盾强效作为装备者自身属性保留，仅进入其作为受盾者时的有效吸收量计算，与其他护盾强效按既有规则合并，不改基础盾量、不传给队友，也不无条件将最终盾量另乘 1.35。四件不限元素，只匹配普通攻击与重击，不加成下落、E/Q 或不接受普通增伤的特殊反应。复用实体护盾能力及既有普通结晶资格和受盾者规则，准备只用于本套，不能反向制造其他效果的触发证据；旧选择不绕过资格与站位。多人贡献及候选计算保留真实 FieldContext，队伍和配置变化重查有效来源，轨迹注明护盾提供者或普通结晶准备。依据固定快照 [RetracingBolide](https://github.com/frzyc/genshin-optimizer/blob/98aafa1f135f086524b611c7d5b5bfb78d98bb6d/libs/gi/dm-localization/assets/locales/chs/artifact_RetracingBolide_gen.json)。

### 4. 当前 Buff 与技能快照不同

复用已有动作 snapshot 语义。当前效果资格与之前是否已锁入技能属性分开判断；不新增默认锁面板，更不能为修站位把全部 Buff 强制动态化，不重构技能 snapshot 管线。

绘卷默认策略（用户已确认）：装备者前后台均允许触发，按队伍与该装备者自身能力默认完成合法反应准备。能在夜魂加持期间触发相应反应时采用 12% + 28% = 40%，只能普通触发时采用 12%，无法触发则不授予该反应对应加成。只给反应涉及元素，不因队友具备夜魂能力就给来源额外 28%，同名效果不重复叠加。

准备资格与当前夜魂状态分开，不因切到后台就删除合法准备的全队增伤。已有 standard/nightsoul 选择兼容到受约束的规则，不能越过来源资格；无法确定反应元素时不默认给七元素。固定快照 [ScrollOfTheHeroOfCinderCity](https://github.com/frzyc/genshin-optimizer/blob/98aafa1f135f086524b611c7d5b5bfb78d98bb6d/libs/gi/dm-localization/assets/locales/chs/artifact_ScrollOfTheHeroOfCinderCity_gen.json) 中的 15/20 秒保留为原始机制描述，不推演持续差异、不增加时间输入。二件套夜魂迸发恢复 6 点元素能量保留机制记录，不折算成充能效率或单次指标直接增伤。

### 5. 唯一判定入口和依赖方向

```text
Content 能力与效果条款 + 现有场景输入
                ↓
Analyzer：FieldContext + 派生能力 + 已确认策略 → 生效/不生效及原因
                ↓
来源属性 / 当前指标 / 多人贡献 / 辅助指标 / 反事实
                ↓
现有公式与来源轨迹 → API → Web
```

共享规则不放进 Calculator；Calculator 不知道圣遗物和站位。治疗/护盾使用同一资格结果，而非强塞进伤害乘区。辅助效果的实体声明逐步迁回各套装目录，共享 helper 只保留无实体知识的解析。

现有 requiresSourceOnField/requiresRecipientOnField 兼容为 applicability 约束；同一效果若新旧声明冲突，作者检查报错。先迁移全部圣遗物，角色/武器不额外改其语义。

资格结果携带来源 ID、受益者 ID、能力证据、默认或显式准备、排除原因；来源轨迹说明采用的计算假设，不伪称已经模拟持续期。被排除的重要装备条款在效果诊断摘要可见，不污染伤害公式为零值假项。

### 6. 性能和一致性

一次完整分析构造共享上下文；每个效果/来源做轻量纯函数判断。多人贡献只变受益者，不变前台。增量精炼请求沿用相同场景，不能重跑整份武器榜。

能力来源在共享场景内解析，查询受益者不会重新创建全队分析。缓存键覆盖实际前台、队伍配置、相关选择及语义版本；更换武器后重新验证与武器属性相关的触发资格，不缓存旧数值。继续复用已实现的属性来源映射，禁止递归进入全量 analysis。

## Risks / Trade-offs

- [静态准备无法证明完整轮转] → 明示假设，不宣称配轴或循环可达。
- [旧最大可达结果下降] → 提供原因；不能为通过历史数值断言而恢复非法 Buff。
- [未知后台叠层机制] → 审计登记证据；不根据文案缺省推断，未核实条款不新增自动触发。
- [能力抽象膨胀] → 仅补本轮消费者需要的类型与角色声明；不增加通用时间线或独立持久化状态。
- [辅助规则遗漏] → 以所有三类效果注册入口做清单检查，不以空 damage effects 判定未实现。
- [多状态来源混淆] → 来源 build ID 与状态 ID 绑定；同名不叠加，不能拿另一套装持有者的状态续期。

## Migration Plan

1. 先引入规则和兼容适配，以现有内容作不变基线；补 [ADR-0023](../../../docs/adr/0023-declare-effect-field-lifecycle.md) 状态确认。
2. 修复审计优先条款及全量分类；保留旧 ID 映射，更新 coverage。
3. 接入辅助、API/UI 和缓存；集中验证跨角色/跨装备场景。
4. 经用户另行授权后再提交和部署；无需数据库或角色工作空间迁移。回滚用同一版本的服务与前端并清理版本化分析缓存，不删用户配置。
