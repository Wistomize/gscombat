## Context

正式数据是仓库内只读 SQLite。genshin-db 只作为新版本输入之一；缺少的链接天赋参数从同版本原始数据补充。

## Goals / Non-Goals

目标为可追溯增量更新与当前角色指标。非目标为全量更换数据来源、循环模拟和线上部署。

## Decisions

- 复制验证哈希的 7.0 SQLite，以事务插入新实体。任何主键碰撞、旧曲线改变必须失败；保留所有旧行及其原始来源。
- 7.1 provenance 分别记录旧库、genshin-db 新增条目及原始 passive 补源，不将旧数据重新标注为新来源。
- 角色和装备使用实体目录与生成注册表；沿用现有直接星扩散、Fpost、生命值转换阶段，不创建另一套计算链。
- 治疗倍率为 Content 可选声明，由通用 healing evaluator 在来源及受疗加成后乘入。条件轨迹增加 less_than，旧枚举保留。
- 重用已算好的来源 HP map，不为每把比较武器新增重复准备。
- 默认版本切换须与内置场景、名称、图标、注册表验证一起完成；未完成不部署。
- 沿用 ADR-0015 的实体声明聚合原则；本次不新增体系架构。
- 用户追加确认：沃雅妮莎水冰与星扩散单次固定加值作为优先辅助指标，复用现有 scalar 求值器；
  与伤害声明共享起算值、倍率、上限，同配置及场景下验证最终来源生命一致。
- 武器前后台集成检查补齐芙宁娜沙龙成员后台标记，避免蝶变退场效果错误保留；不增加角色特判。
- 冻结是共享环境快照，传入来源属性准备与辅助指标上下文；装备目录从 lifecycle 自动投影必要开关，
  Web 不写武器 ID 分支。目录与辅助请求仅增加可选字段，旧请求保持默认未冻结。

## Risks / Trade-offs

阶段数据可能暂时已生成而默认版本未切换，任务状态必须明确标示。
辉映替换分支不能同时生效；前后台来源与受益者必须分开。
新增治疗倍率需严格校验 39.9%、40% 和 40.1%。
