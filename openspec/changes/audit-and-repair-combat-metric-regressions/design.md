## Context

动机见 [proposal.md](proposal.md)，逐项证据见 [audit.md](audit.md)。这是对真实已上线错误的修复，不是再启动一轮全角色功能扩展。

旧 `complete-cumulative-constellation-semantics` 仍有未完成任务，不能将勾选状态或发布记录当作正确性证据。工作区已有木偶和轨迹改动必须单独复核；本 change 不覆盖或回退这些改动。

## Goals / Non-Goals

**Goals:** 用可定位的正确性规则解决清单 R01–R24，保留真实事件身份、来源、概率和乘区，确保分析结果、轨迹、武器比较和词条收益一致。

**Non-Goals:** 不建立循环模拟/通用实时状态系统，不重排仓库架构，不顺带重写其他武器套装；不把待确认项自动当成确定修复。只读扫描不是每个角色的全机制认证。

## Decisions

### 1. 公共修复先行，内容分批消费

顺序为 B0 既有修复/守卫、B1 事件存在性/加算/继承/概率、B2 有效依赖、B3 参数与变体、B4 辅助、B5 前台与反应、B6 验收。每批以其精确反例验证，批量表示按根因组织，不表示一次大补丁后只测总数。

依赖方向保持 `apps → analyzer → content/game-data/calculator`；Calculator 不包含角色 ID 特判。长期约束记录在待审 [ADR-0020](../../../docs/adr/0020-preserve-explicit-event-effect-eligibility.md)，延续 ADR-0006/0010/0014。

### 2. 事件存在性不由倍率推断

普通伤害时间线复用已有 minimum/maximumSourceConstellation、命中门槛；无效事件在基础项解析前排除。纯组织代理改成非命中组织方式，或直接让现有真实伤害事件构成动作，不产生代理伤害。保留合法的零天赋倍率加固定伤害事件。

否决 `coefficient === 0` 全局删除，以及用零值压住未解锁事件的方案。范围首先覆盖流浪者和爱可菲六段；卡齐娜仅在有实际匹配加算反例时纳入。

### 3. 角色追加事件的类型化资格和完整基础区

在现有 Content 事件声明上增加最小可选的父动作效果继承范围（按明确 effect ID 或已审阅动作身份限定），默认保持独立武器触发事件隔离。基尼奇炮类 C1、丝柯克普攻状态 C2 明确声明；不全局放开 `targetFilter.actionIds`。

Analyzer 为实际事件重新解析适用效果，再复用基础伤害组装：天赋项、适用同段项、符合该命中的固定加算。不能只携带 appliedEffectIds 却漏掉其数值，也不能从父事件复制已经结算的总伤害。

概率明确为“事件发生概率”，完整事件按一次实际触发计算后再加权，轨迹显示单次值、概率和期望。若现有 Calculator 事件类型不能表达，增加缺省为1的可选概率字段；不要把概率藏进系数或暴击率。原有云堇/冰翎次数假设保持显式，不宣称模拟跨整个循环的消耗。

### 4. 有效状态再建立依赖

先解析请求选择和最大可达候选的来源、命座、条件和互斥，再由已满足的父效果计算依赖；不能把原始 activeEffectIds 当作资格。循环或不可满足依赖须终止，不进行无界固定点计算。

兼容策略：对因改队留下的不适用选择按既有归一化规则忽略或现有校验错误处理，绝不因此给额外伤害。基尼奇心得直接归入对应弹跳的同段项，不为同段追加量另造独立命中。

### 5. 语义参数与别名绑定

R07–R14 逐项对照固定上游的参数身份和本地数值，不以更新 snapshotChecks 代替语义审阅。攻击/生命/防御/精通使用受控属性扰动验证；C3/C5 等级沿既有角色统一规则累计。

玛薇卡别名用明确的规范动作关联，不再从字符串后缀猜继承。保留旧请求可解释性，隐藏重复公开变体；所有指向同一无反应语义的 ID 使用同一规范声明解析基础项和效果。沿该公共路径检查其他已存在别名，不无条件改全部反应标签。

### 6. 辅助来源属性和完整公式

修复辅助来源解析只收装备 automatic 的缺口，让来源角色 automatic 与 maximum_reachable 属性效果在各自条件下进入同一来源面板；保持团队/接收者范围，不能把所有队伍增益混入来源自身。

- 迪奥娜：HP 治疗、C6 HP 来源、C2 整盾三项分别验证。
- 早柚：现有 additionalScalingTerms 加 `3 × EM`、C6门槛、6000上限，无新求值器。
- 莱依拉/迪奥娜：增加或复用 scalar 的“最终基础盾倍率”类型化节点，作用于 `HP×比例+固定值` 全部，而非仅比例项。
- 梦见月点心：受益者为来源本人时应用专属×2；不把它加到普通治疗加成池，不改变队友治疗值。

### 7. 前台互斥和普通扩散 C1

为相关效果声明来源前台要求，为涉及的核心动作声明必须前台或可在后台。只比较固定场景的角色资格，不模拟实际时间。梦见月梦浮系列增益统一受相同资格约束；奥黛塔前台破晓终奏为负例，真实后台队友为正例。

来源属性求值将某个队友临时设为属性接收者时，必须保留真实动作所有者 `actionOwnerBuildId`。该身份贯穿精通分享前/后两阶段，避免把后台来源误当成站场角色，再通过晚星等转换间接泄漏增益。

沿用户既有最大可达前提处理可合理达成的层数，不能同时假设两名角色占前台。未知动作资格不从标签强推，也不默认视为后台：队友要求来源站场的增益只对明确声明 off_field 的目标生效，迁移相关后台指标时明确补声明。梦见月普通扩散 C1 使用已有后置固定伤害能力；当前单次扩散指标只计算该次反应，保留星扩散组合中独立额外攻击的现有口径。

### 8. 精简但能抓错的验证

实施全测追加确认 R25：来源精通拆分遗漏团队装备贡献。修复沿用本方案“来源属性完整、资格不扩大”的边界，将角色、自身装备、团队装备三组非递归贡献分开采集。团队装备仍复用来源/装备/触发条件校验；后置比例精通分享只读分享前快照。无需新增依赖图、状态机或角色特判。

审查 probe 仅保存复现证据，不加入常规测试启动链。实施时收敛成少量参数化集成测试：每种公共机制覆盖正反例，角色内容表仅维护必要参数身份守卫，不为每个角色写大量相似单测。

修复不得改变正确断言去迎合实际数值。最终运行 Content registries:check、相关集成测试和根目录 `pnpm typecheck`、`pnpm test`、`pnpm build` 一次完整门禁；有失败就定位，不能宣称“原有失败”后忽略发布。

## Risks / Trade-offs

- [父动作增益过度继承] → 显式许可范围，保留武器 proc 负例和错类别负例。
- [零倍率事件被误删] → 按资格与组织类型过滤，不按伤害是否为零过滤。
- [修基础区后一次加算被算两遍] → 对每个真实事件断言基础项、来源与总和；去掉代理贡献。
- [状态推断扩张] → 只做静态前台资格，拒绝完整状态机；相对层数取满但互斥状态不可同时成立。
- [新别名解释影响旧请求] → 规范动作映射和 HTTP 兼容回归，不静默换目标含义。
- [上游也不确定] → 绫人 C6/C1 等移入待核实清单，不能借本次批量修复直接猜测。
- [已在本地修复与新审查基线混用] → B0 先记录各项 baseline，测试数据注明是否包含已有 dirty 修复。

## Migration Plan

无需用户数据、SQLite 或固定游戏数据迁移。保存的角色配置继续可用，结果根据修正后的公式重算；若清理重复指标 ID，服务端保留明确兼容解释。

本轮只产出方案。批准后按 B0–B6 完成并报告剩余问题；提交/推送/部署须独立授权。发布时构建同一已验证 Git revision 的 API/Web 镜像，核对实际运行镜像和受影响场景，保留上一镜像用于有明确授权的回退。不能仅检查服务器 Git HEAD 就宣称线上已修。

待核实项不影响确认队列的开始，但不得被算入完成数量；若事实核查要求超出本设计的新机制，暂停对应项请求裁决，不阻塞已明确的小修复批次。

## B7 Follow-up（2026-09-10 用户批准）

艾梅莉埃 C6 两项沿用 `active` 效果表达目标正在燃烧，以 `source_final_attack` 读取当前实际攻击乘以0.00015、上限0.36；仅绑定这两个动作，不与已自带燃烧前提的二阶柔灯 intrinsic 重叠。不会根据有火队友或未竟套效果推断目标燃烧，也不新增全局敌人状态。

卡齐娜加叶洛亚（匣里灭辰提供非零精通）已复现代理额外取得岩伤基础加算；真实C6事件还漏掉父动作绑定的C4防御。使用已有 `hitCount: 0` 和显式 `inheritedActionEffectIds`，分别消除代理贡献和恢复真实事件C4面板。不修改公共求值器、伤害类别及指标口径。

本补充只改两个角色的既有声明及两组集成回归；采用 tasks 8.3 的比例验收，上一轮全仓发布门禁结果不冒充本次重新运行。

## B8 梦见月星扩散指标拆分（用户批准）

旧 combo ID 保留但修正为直伤（1000%精通 + C1解锁时400%精通），新增 single_stellar_swirl 仅含一次风反应，C1的550%精通后置加算只绑定新反应事件。名称明确梦浮/辉映及标记触发前提。普通扩散和两个治疗不变，不增加C1独立指标，不纳入普通周期风伤或风旋冰伤。

允许 damageParts 为显式空数组的纯星扩散反应时间线，仍拒绝没有任何事件的空动作，禁止用伪零命中绕过校验。风反应在固定冰底场景下只将本次触发者及冰元素队友作为贡献者（冰队友预设仍有有效附着），其他队友仍提供合格辅助。无冰队友可按外部冰底计算触发者贡献。保留当前逐暴击组合排序/60-30-5-5系数；不声称已经解决来源资料的排序争议。参与者取属性时保持实际动作所有者，确保梦浮团队精通、增伤与双暴仍有效。

本批复用已有 Content 声明与事件流水线，不改 HTTP 数据形状、不增加实时状态系统；验证 Content 全测/注册表、Analyzer 聚焦系统及集成、API两指标完整分析和相关包构建/类型检查。遵循用户避免过度测试的要求，不重复本 change 已完成的 Web/全仓发布门禁；提交部署仍需另行授权。

## B9 星扩散元素限定权重与冰风旋（用户批准）

在现有逐暴击组合求期望的聚合函数中，为星扩散传入各权重位置的元素资格：风[风,不限,不限,不限]，冰[冰,风,不限,不限]。每个位置从尚未选择的参与者中挑符合资格且本次伤害最高者；缺少合格者，该位置贡献为零，不将其他元素提到该位置。月反应不传限定，继续纯伤害排序；直伤不进入聚合。保存每个参与者本次实际权重，防止缺位时按压缩后的数组下标错误加权。输入的元素是角色元素，不是统一的伤害元素。

冰风旋使用固定已参与风旋的风/冰队友快照（其他元素只供辅助），不模拟历史附着、风旋刷新或冰底消耗。保留梦见月为真实前台：团队精通、星扩散加成和C6双暴合法；C1的550%仅绑定风触发，冰爆炸不自动取得。无冰参与者时不捏造冰来源，保留风参与者的30%位置并明确公式说明缺位为零。

Content新增 single_stellar_swirl_vortex，element=cryo，复用纯反应事件；scenarioParameters声明vortex_level整数1–6/默认6，事件通过参数引用读取。底层vortexLevel由原内部“两档”改为实际1–6级，不新建档位切换器。旧公开指标此前没有风旋参数，因此无需用户配置迁移。运行时及作者审计同时验证引用和范围，不能悄悄截断无效输入。

沿单一链路将等级、反应系数和元素限定规则展示在轨迹；HTTP分析响应增加可选vortexLevel，覆盖接口的事件声明同步允许1–6级字面量或parameterId引用；不增加必填请求字段，前端复用通用动作参数选择。涉及calculator/content/analyzer/contracts/api/web，延续ADR-0006及ADR-0020的事件归属边界，无需新架构层或ADR。

验证采用少量聚合公式正反例、真实场景与API分析（两等级档、C1隔离、目录默认值）及Web通用参数/公式渲染。相关包全测或聚焦测试、类型检查和构建按比例执行；不重复前面已完成的全仓发布门禁，不提交部署。依据用户提供的羽化哲公式及强度研究院口径；与梅信心说明的分歧记录保留。
