# GSCombat 玩家优先 README 设计

## 目标

仓库根 README 的首要读者是使用 GSCombat 的《原神》玩家，而不是参与代码维护的开发者。README 应在首屏回答：

1. GSCombat 能解决什么问题；
2. 它与固定圣遗物评分或普通伤害计算器有什么不同；
3. 玩家如何立即开始使用。

## 叙事原则

- 从“当前配置能打多少、换装备能提升多少、为什么”这个玩家问题出发；
- 先介绍目标伤害、辅助指标、边际收益和公式追踪，再介绍限制与数据保存；
- 使用界面中的中文名称，避免在玩家段落中暴露包名、类型系统和内部接口；
- 明确当前计算对象是核心动作期望结果，不将其包装为完整循环 DPS；
- 不使用无法解释的统一圣遗物总分，强调相同场景下的反事实重算；
- 中英文 README 保持相同信息结构，但不要求逐句直译。

## 信息结构

根 README 依次包含在线入口、产品价值、能力分类、使用流程、结果解释、计算理念、保存与同步、当前边界、
反馈与声明。仓库结构、本地运行、Content 声明、测试、数据更新和部署迁移到独立开发指南，只在 README 最后链接。

## 后续扩展

如果增加产品截图或演示视频，应放在首段价值说明之后、能力列表之前。截图必须来自当前线上版本，并避免包含 UID、
邀请码或个人角色配置等敏感信息。功能扩展时优先更新玩家能观察到的结果与边界；实现细节只更新开发指南和架构文档。

## 验收标准

- 玩家无需理解项目架构即可知道如何导入配置、组成队伍并开始计算；
- README 能准确解释指标结果、结算轨迹、边际收益和武器比较；
- 开发信息完整迁移且所有相对链接有效；
- 中文、英文与当前线上功能一致。
