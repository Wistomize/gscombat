# ARCH-006 API 组合根拆分计划

## 目标

将 `apps/api/src/app.ts` 从路由、序列化和资源生命周期的混合实现收缩为 API 组合根，同时保持现有 16 个 HTTP 路由、Schema、响应结构、错误码和依赖注入选项不变。

## 边界

- `app.ts`：创建 Fastify、构造共享资源、注册关闭钩子、装配路由。
- `routes/`：按会话工作空间、目录审计、分析、展示柜划分 HTTP 适配器。
- `serializers/`：把领域对象复制为稳定、可 JSON 序列化的公开响应。
- `services/`：放置工作空间、展示柜和动作效果等基础设施或应用服务。
- `test/`：保存 API 集成测试与结构守卫，生产目录不再混放测试。

## 实施次序

1. 冻结 16 个路由、`app.ts` 的 6 个公开导出和 API 14 文件 134 项测试基线。
2. 抽取分析、辅助指标、覆盖报告和 Catalog 序列化函数。
3. 抽取四组路由注册函数，每组只接收自己需要的依赖。
4. 将现有工作空间、展示柜和动作效果实现归入 `services/`，不改变实现。
5. 将 API 测试迁入包根 `test/`，加入组合根、依赖方向、无环和跨包导入守卫。
6. 验证 API 类型、构建、集成测试，再运行全仓门禁。

## 不做的事情

- 不改变 URL、HTTP 方法、Schema、Cookie、限流、SQLite 或 Enka 行为。
- 不改变 Analyzer、Content 或 Calculator 的计算语义。
- 不为路由引入容器、装饰器、自动扫描或第二套状态系统。
- 不提前处理 ARCH-007 的 Web/API Catalog 来源统一。

## 完成标准

- `app.ts` 不直接声明业务路由或响应投影。
- 路由模块不实现伤害公式，只调用公开领域入口并序列化结果。
- API 生产依赖图无环，跨包代码不导入其他包的 `src`。
- 公开导出、16 个路由及全部集成测试保持不变。
