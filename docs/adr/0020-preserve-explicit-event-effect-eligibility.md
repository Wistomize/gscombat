# ADR 0020: 显式事件增益资格与有界状态

## 状态

已采纳（2026-09-10）。用户已批准 `audit-and-repair-combat-metric-regressions` 方案，相关实现已完成；本地验收不代表已经部署。

## 背景

角色命座追加伤害复用独立武器触发事件通道后，出现角色普攻漏基础区、炮类追加漏自身暴伤、零倍率占位制造假命中，以及按请求 ID 而非实际生效条件激活依赖伤害的问题。梦浮仅修单项精通的接收者，也没有解决同一前台状态下其他增益互斥。

## 决策

- 保留 ADR-0006 的动作内事件、ADR-0014 的单一权威求值流程；角色身份、倍率和条件仍由 Content 持有，Calculator 不导入角色。
- 真实角色事件携带最小显式资格：自身攻击类别/元素、解锁条件、触发概率，以及允许继承的父动作绑定效果范围。缺省不扩大武器 proc 的继承权限。
- 复用统一基础项组装规则；概率在完整事件结果层加权，占位组织节点不参与命中结算。
- 效果依赖只以条件/来源/互斥校验后的有效状态为依据；无效父状态不激活子项。
- 仅为需要纠正前台互斥的场景增加静态“来源必须前台”和“目标动作必须前台/可后台”声明，不模拟切人、时间推进、冷却或实时状态机。
- 未声明前后台资格的目标不推定为后台；队友要求站场的效果只对显式后台动作放行。来源自己的合格动作继续遵守原有命座与条件。
- 临时更换来源属性接收者不改变真实动作所有者；来源快照同样遵守前台互斥，防止增益通过装备转换间接泄漏。
- 治疗/护盾复用角色来源属性解析和类型化公式节点；整盾倍率与受益者专属治疗倍率保留其正确计算位置，不能伪装为 HP 倍率或普通治疗加成。
- 来源精通按角色、自身装备、团队装备三个互斥集合采集，再进行非递归的精通分享，不能因拆分丢掉团队装备固定增益。

## 备选方案

- 全部追加事件继承父动作全部效果：拒绝，会把专属命中倍率、反应增益等错误扩散到武器 proc 和其他事件。
- 所有零倍率事件都删除：拒绝，真实事件可能以固定加算构成伤害；应按事件资格而非结果数值判断存在性。
- 每个角色单独修补数值：拒绝作为公共根因方案，会重复漏基础区和概率逻辑；角色声明修正仍需要保留。
- 建立完整战斗状态机：拒绝，超出单个核心动作固定场景边界。当前只需静态资格判定。

## 后果与验证

共享可选类型保持旧声明和外部请求兼容。少量组合集成用例必须同时覆盖角色正确继承与武器不误继承、无效状态负例与合法后台正例。新增机制事实若无法由既有证据确定，保持待核实，不以最大可达为理由假设互相冲突的状态同时存在。
