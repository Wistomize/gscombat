# ADR 0003: 用语义动作侧边表引用固定快照

## 状态

已采纳。

## 背景

固定的 Genshin Optimizer 6.7 SQLite 快照提供角色基础属性、武器、圣遗物数值，以及按
`characterId / groupId / parameterIndex / talentLevel` 存储的天赋参数。它不保留玩家可见的
动作名、命中段数、元素附着、锁面板时点、ICD 或条件逻辑。

把参数数组自动解释为完整角色技能会把未知语义误当成可计算数据。另一方面，将倍率复制到
内容代码中会让版本更新时难以发现漂移。

## 决策

每个可计算动作在 `packages/content` 中维护一个很小的语义侧边表：

- canonical character ID；
- 动作 ID、元素、缩放属性与命中段；
- 固定快照中的 `groupId + parameterIndex` 引用；
- 经过人工校验的 L1/L10 金样值；
- 选择的通用计算器或专用角色计算器。

运行时只读取本地 SQLite 快照，不向任何外部数据库请求倍率。`combat-registry-integrity`
在测试和快照更新时验证角色、参数引用、命中段引用以及金样值。一个角色可以保持 `draft`，
同时含有若干 `verified` 动作；这表示该动作的已声明范围可计算，并不声称整个角色循环已经
完整模拟。

## 后果

- 可先交付可解释的单目标期望伤害，并逐步补充角色状态、Buff 窗口、反应和完整循环；
- 快照变更会以明确失败的测试暴露语义映射漂移；
- 需要开发者逐个审阅动作语义，不能由裸参数数组批量伪造完整角色逻辑；
- 新角色/旅行者变体需要先建立 canonical ID 与动作语义映射，之后才能标为可计算。
