# ADR-0023：区分效果触发、保持与受益站位

## Status

Accepted（2026-09-17 用户批准实施）。迁移与验证状态见变更任务表。继承 [ADR-0022](0022-preserve-scenario-field-identity.md)。

## Context

场景唯一前台身份只回答“谁在场”。同一套圣遗物可以同时有常驻加成、需要前台触发的持续增益以及全队受益，单个 on/off 布尔无法表达。审查见 [63 套清单](../../openspec/changes/model-artifact-field-lifecycle/audit.md)。

## Decision

Content 按条款声明触发资格、命中时条件、保留规则和受益对象；Analyzer 使用唯一 FieldContext 与有限的准备状态求值。使用静态单动作模型，不构建轮转时间线。效果窗口与来源关联；同一触发的多个属性共享状态。

前台触发不等于命中时前台；后台可触发不等于增益给全队。切人清除动态 Buff 与已经锁入动作的属性快照分开。默认值使用明确、可解释的准备策略，不能把最大可达当作无条件成立。

伤害、治疗与护盾仍使用各自公式，但共享资格判定。声明留在实体目录，公共层无圣遗物 ID 分支。第一轮迁移圣遗物，现有角色/武器的前台标志经兼容适配使用同一资格判定，不借机全量重写。

能力声明位于角色 `combat.ts` 与装备实体，生成注册表只汇总；`scenario/capabilities.ts` 查询来源、对象、站位与条件，`scenario/effect-lifecycle.ts` 判断准备和保留。已确认的十秒施放/七秒命中机会引用固定数据库冷却、充能、连段和明确重置，不变成逐帧事件或存档字段。

需要前台预触发且退场保留的规则，仅在准备资格查询中使用来源的前台身份；命中时的 FieldContext、受益者以及其他贡献者均保持原样。切人清除或实时条件直接检查真实站位。

API 的可选 `artifactPreparations` 返回当前基准的准备解释，区分“有资格”和“实际作用于本指标”。网页本地目录与 API 目录复用同一条件投影；候选精炼不重新生成完整说明。不存在跨请求结果缓存，本次沿用冻结场景与请求 generation 失效机制，并升级分析语义版本。

## Consequences

- 正向：可以同时正确处理前台独享、后台额外、退场清除及全队持续加成；反事实保持同一场景。
- 代价：声明需维护触发证据及准备策略；只保留用户明确确认的选择，不新增登场秒数或短暂窗口输入。
- 限制：不证明整队轮转的时序可达性，不模拟概率、治疗记录或自动层数时间轴；输出必须披露默认准备假设。
- 性能：按场景构造、缓存一次规则状态；不能为每个贡献者重新构造完整队伍分析。

## Alternatives Considered

- 只加 requiresSourceOffField：无法表达触发与持续、登场宽限，拒绝。
- 每套 Analyzer 特判：重复且无法保证来源属性/武器比较一致，拒绝。
- 全角色动作时间线模拟：超过单指标产品边界，拒绝。
