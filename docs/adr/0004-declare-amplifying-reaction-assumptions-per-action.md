# ADR 0004: 将增幅反应前提声明在目标动作上

## 状态

已采纳。

## 背景

固定快照提供元素、倍率和角色面板，但不提供一段伤害发生时的元素附着、ICD、队伍切人时点或
水/火底是否稳定存在。直接把“蒸发”写成一段独立追加伤害会错误地绕过暴击、增伤、防御和抗性
乘区；只把反应传给 rotation，又会使 API 的期望伤害、武器比较和词条边际收益继续使用未反应值。

## 决策

对已经人工确认元素前提的单目标动作，在 `CombatActionMetadata` 声明可选的
`amplifyingReaction`：反应类型和额外反应加成。声明式直伤求值器把它同时传给可解释的单击
期望伤害管线和 rotation 事件；两条路径复用相同的增幅反应公式。轨迹在倍率区后单独展示增幅
反应区，包含基础倍率、元素精通、反应加成和最终乘数。

当前只允许动作级声明，因此它表示该动作的所有命中段共享同一个反应假设。香菱的目标动作
`xiangling.burst.pyronado.reverse_vaporize` 明确表示“单次旋火轮在水底触发蒸发”，不是完整
元素附着模拟。

## 后果

- 水底蒸发的元素精通、武器比较和圣遗物词条收益会进入同一份结果；
- 页面会显示该假设和完整公式，不会把蒸发伪装成额外的独立伤害；
- 没有稳定元素底、不同段反应不同、ICD 或锁面板时点的动作必须拆分为多个语义动作，或使用
  专用 rotation evaluator；
- 角色覆盖仍保持 `draft`，直到其完整的附着、时序、状态和条件效果被建模。
