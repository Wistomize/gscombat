# ADR-0022：在场景中保持唯一前台身份

状态：已接受，用户于 2026-09-10 确认。

## 背景

单次反应可能读取多个角色的伤害贡献及属性转换。临时把贡献者设置为 primary，并不代表发生切人；若复用其动作站位或默认视作前台，会同时授予多个角色前台限定效果。

## 决策

在 [ADR-0014](0014-use-one-authoritative-scenario-metric-evaluation-path.md) 的单一求值链路中使用不可变 FieldContext。它保留 actionOwnerBuildId 和 onFieldBuildId，后者可以为 null，表示后台动作的前台队友尚未指定。

Content 的 fieldPresence 只声明指标所属角色的站位约束，不承担实时场景身份。旧未标记动作按所属角色前台兼容；明确后台动作可以通过可选场景条件指定其他队员前台。非法队员、与指标冲突的选择被拒绝。

来源 requiresSourceOnField 和受益者 requiresRecipientOnField 分别检查实际身份；未知不当作前台。属性来源快照、参与者贡献、原指标和反事实重算传递同一上下文。全队与敌方效果不因受益者后台而失效。

不为每个角色 Build 保存站位，不把贡献求值建模成切人，不引入全局可变状态。持续、锁面板和施放时条件不能仅凭“领域”或“当前角色”文案自动转换为命中时前台限制。

## 后果

后台指标的结果可能因移除未经确认的前台收益而降低；Web 提供前台队友选择，旧配置仍可加载且无需迁移。其他调用方可以继续省略该可选条件，此时不授予需要确认前台身份的效果。

核心反应公式保持无角色知识，元素加权位置仍属于 Calculator。完整队伍传给加权器，不能用前后台身份过滤参与人数。来源属性映射仍每次动作只构造一次，不恢复逐队员重复重算。
