# ADR 0021: 无状态单候选武器比较

- 状态：已采纳，已完成本地实现与验证；发布状态以实际部署版本核验为准
- 日期：2026-09-10

## 背景

精炼调整目前触发整个分析报告重算。局部更新需要受支持的调用边界，但不能恢复 ADR-0014 消除的第二套计算模型，也不应要求服务端保存用户报告。

## 决策

- `/v1/analysis` 保持完整报告契约，增加 `/v1/analysis/weapon-comparison` 子资源。
- 子资源接收完整场景和一个候选，在服务端求基线与候选；复用全量比较的候选资格、条件迁移及权威场景求值。
- 不接受客户端数值基线，不使用报告 token 或跨用户场景结果缓存。
- Web 以固定报告场景和请求世代合并单行，丢弃过期响应。
- 固定数据库查询结果仅在有界的仓库实例内复用；计算来源快照仅在同一场景变体内复用，不跨候选沿用最终队友属性。

## 备选与后果

给完整接口增加部分返回模式会扩大原响应契约；服务端保存报告会增加失效与用户隔离要求，均暂不采用。新增 HTTP 子资源并不新增伤害求值链路，未来批量/局部优化仍需复用同一候选规则。

旧客户端兼容；新客户端需 API 先行部署。单候选仍要计算基线和队伍影响，但成本不随其他候选数量增长。

## 2026-09-27：统一装备与候选准备规则

本次[规则迁移](../../openspec/changes/implement-reviewed-weapon-default-rules/design.md)保留上述无状态边界。
自动准备、必要选择及比较资格由 Content 实体声明；实际装备和两种比较入口统一解析，
不再保留仅向候选补 Buff 的 `weaponComparisonDefault`。必要选择按来源 Build 隔离，
候选覆盖仅作用该行；场景共同条件、精炼和选择均进入请求签名及世代检查。

候选范围包含支持的三/四/五星，具体排除与合法等级由实体的比较策略声明。
API 可选字段向后兼容，新增逐事件属性来源用于准确轨迹；分析语义版本升级不迁移或删除用户配置。
放弃继续维护双套默认的理由是：即使两套总伤害当前一致，后续条件与队伍资格更新仍易分叉。

## 2026-09-28：请求内准备复用

本次[性能重构](../../openspec/changes/optimize-scenario-preparation-reuse/design.md)保持数值、轨迹与接口契约不变：

- Content 在模块加载时建立固定声明列表、ID 和来源索引；来源候选仍按原声明顺序返回，动态资格判断留在 Analyzer。
- 每次完整分析或单候选比较拥有一个私有 `AnalysisPreparation`。裸属性按精确 Build 对象和伤害元素复用，绑定当前 GameData 仓库实例；相同 buildId 不代表相同配置。
- 一次场景求值创建一份 `SourcePreparation`，HP/ATK/DEF/EM 共用来源身份、裸属性及相同条件的自身自动装备解析。精通分享前后、充能转换、最终属性转换仍各自按原阶段计算。
- 换武器、词条和成长干预仍经过完整权威求值；只复用未变的纯输入，最终面板、动态选择、事件和前后台状态不跨候选缓存。辅助来源属性也使用同一来源准备函数。
- 缓存不存到模块全局或用户工作空间，公开调用结束即失去持有者。公开单指标入口始终创建独立上下文。

没有引入线程池、第二套数据库缓存或仅数值的近似计算路径。没有证明是热点的元数据查询继续使用现有实现，避免扩大缓存失效边界。
