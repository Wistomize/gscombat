# ADR 0005: 用同一固定提交的本地化资产辅助动作标注

## 状态

已采纳，导入器将作为构建期作者工具接入。

## 背景

当前本地 SQLite 快照可靠保存了天赋参数数组，但数组下标没有玩家可读语义。以香菱为例，
`burst[3]` 只有数值；仅通过数值不能安全判断它是旋火轮、持续时间还是能量消耗。把裸参数
自动标为可计算动作会伪造战斗逻辑。

同一份固定的 Genshin Optimizer 提交已包含受版本控制的本地化资产：
`libs/gi/dm-localization/assets/locales/{en,chs}/char_<CharacterId>_gen.json`。这些资产将同一
天赋组中的 `skillParams["参数下标"]` 显式映射到标签；它们不是可按长度直接对齐的数组。例如，香菱中文资产明确把
`burst[3]` 标为“旋火轮伤害”。

## 决策

将本地化资产视为与 `allStat_gen.json` 相同上游仓库、相同提交的构建期语义资产：先下载、校验聚合哈希并写入独立
预览 sidecar。线上服务仍只读取默认本地 SQLite，不会因角色计算请求外部 API，也不会使用 Genshin Optimizer 的
子模块、Hakushin 缓存或其他运行时数据源。

本地化标签只用于生成和审阅作者工作项；一个 `verified` 动作仍必须由开发者显式声明元素、
缩放属性、命中段、反应、ICD、时序、锁面板和 L1/L10 系数锁。标签不足以自动推出这些逻辑。

## 后果

- 117 个常规角色可以批量获得普攻、战技、爆发名称和参数标签，减少手工查索引的成本；
- 预览导入会按非空 `skillParams` 下标与数值参数逐项核对，允许固定空槽，但会报告缺失或越界标签；
- 旅行者变体和本地特殊角色仍需显式映射或手工回退；
- 公开部署时要保留来源归属，并在发布前单独审查底层游戏文本的使用边界。
