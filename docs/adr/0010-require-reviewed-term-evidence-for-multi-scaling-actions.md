# ADR 0010: 多倍率动作必须有审阅过的术语映射证据

## 状态

已采纳。

## 背景

固定的 6.7 SQLite 快照能稳定给出天赋参数的数值与等级表，本地化 sidecar 能给出大部分
`groupId / parameterIndex` 的玩家可读标签。两者都不能单独证明一个动作的所有倍率项属于同一
次命中、分别缩放于哪种属性。

艾尔海森战技揭示了这个限制：固定数据中的 `skill[0]` 为 `1.936 → 3.4848`，`skill[1]` 为
`1.5488 → 2.78784`；数值形状与一次攻击力和元素精通双倍率命中相符。但同一固定中文资产把
`skillParams[1]` 标为“光幕攻击间隔”，而 `skill[2]` 的 `1.6` 才符合间隔。sidecar 导入器按
同一索引机械配对，且 ADR 0005 已明确它不推断缩放或技能逻辑。因此，把第二项自动写成元素
精通倍率会把一个可疑的展示映射升级为公开伤害结论。

## 决策

单一缩放、标签和命中语义明确的动作仍可按 ADR 0003 的方式声明。一个动作只要包含两个或更多
`scalingTerms`，则在标记为 `verified` 前必须有显式、人工审阅的术语映射证据，逐项说明：

- 原始参数路径、所属命中和缩放属性；
- 每项在最低与最高审阅天赋等级的金样值；
- 为什么该项不是持续时间、间隔、治疗、消耗或另一段命中；
- 来源锁定到固定上游提交或一份版本化的审阅映射资产。

本地化 sidecar、数值相邻性、或外部模拟器的交叉验证都只能帮助发现候选，不能单独满足这个
门槛。若证据不足，动作保持未建模；不得为了覆盖率把它降级为错误的单倍率动作。

## 后果

### 正面

- 元素精通、生命、防御等非攻击倍率不会因标签错位被静默计算错。
- `verified` 继续表示可解释、可复现的声明，而不是“数值看起来合理”。
- 后续建立审阅映射后，现有 `scalingTerms` 和计算器无需再设计一次。

### 负面

- 一些常见角色技能会晚于单倍率基础动作进入可计算范围。
- 作者需要维护额外的来源和审阅记录，不能只批量读取 `skill[0]`。

### 中性

- 艾尔海森的普通攻击基线和重云领域兼容标记保持有效；其战技的攻击力加元素精通双倍率命中
  在证据齐全前仍不出现在可选动作中。

## 考虑过的替代方案

### 按本地化数组下标直接配对

拒绝。该案例说明同一展示行可以与原始数值参数错位，且 sidecar 本身不承担机制推断职责。

### 仅依据外部模拟器或攻略补齐术语

拒绝作为唯一来源。外部实现适合作交叉验证，但公开服务的可复现数据基线仍应由固定快照和
版本化的审阅映射持有。

### 先按攻击力单项近似计算

拒绝。省略已知的元素精通项会系统性低估，并会误导词条边际收益和有效词条分析。
