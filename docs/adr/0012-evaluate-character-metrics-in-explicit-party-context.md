# ADR-0012: 在显式队伍上下文中结算角色指标并返回公式轨迹

## Status

Accepted

## Context

伤害、治疗、护盾、数值增益等角色指标不能共享一个数值单位，也不应都被换算成某个当前主 C 的伤害
提升。此前的首版指标模型只读取来源角色自身属性，适合验证班尼特的基础治疗和领域加攻，但无法表达
“哪个队友实际收到治疗”、受疗加成、是否在领域内、当前生命值门槛等真实结算条件。

班尼特说明了这个问题：单跳治疗的来源公式由班尼特的生命值、天赋和来源治疗加成决定；最终给某个
角色的实际治疗还会受到受益角色的受疗加成及领域、生命值条件影响。把它固定折算为某个主 C 的伤害
收益会再次引入动作、反应、时序和快照假设，且不能代表班尼特本人的输出。

前端最终需要解释每个指标的计算式，但不同辅助机制没有一个可由内容数据任意拼装的通用公式。任意
表达式 AST 或回调会削弱对固定游戏数据快照、天赋参数和条件的审计能力。

## Decision

保留由维护者声明的强类型 `damage`、`healing`、`stat_buff` 指标定义，并为其增加显式目标语义：

- `damage` 的目标为敌人，继续复用当前单次核心动作的完整伤害流水线和伤害轨迹；
- 支援指标的目标为一个显式选择的友方受益角色，运行时输入包含来源角色、队友列表和受益角色状态；
- 受益角色状态按需声明，例如是否在来源领域内、当前生命值比例、受疗加成和精确生命缺口。没有提供一个被该指标
  需要的状态时，求值失败而不是猜测默认值；
- 内容声明可给友方指标附加经过校验的条件。班尼特的治疗要求“领域内且生命值不高于 70%”，领域
  加攻要求“领域内且生命值高于 70%”，其中加攻生命门槛可由 1 命解除；
- 每个结果同时返回 `potentialValue`、条件后的 `value`、逐项条件结果和可递归渲染的公式树。治疗还保留
  `sourceValue`；当调用方提供精确生命缺口时，额外返回 `actualRestoredValue` 及其封顶公式，明确区分
  来源可提供治疗、可结算治疗和实际恢复生命；
- 公式树只是执行结果和展示数据，不是内容作者可自由编程的计算语言。每新增一种机制，先新增受审计的
  类型化执行器和对应公式节点。
- 可由装备本身静态决定的自增益圣遗物效果在内容层显式维护，并在来源属性解析时计入。当前已纳入少女、
  海染和昔时之歌的两件套治疗加成；其余套装或条件型效果仍须先有经审计的内容声明。

班尼特的当前单跳治疗被表达为：

`[(来源生命 × 治疗百分比 + 固定治疗) × (1 + 来源治疗加成) × (1 + 受益角色受疗加成)] × 条件`

当受益角色提供精确生命缺口时，实际恢复生命再结算为：

`min(条件后的单跳治疗量, 受益角色当前生命缺口)`

班尼特领域加攻被表达为：

`[来源基础攻击 × (天赋加攻倍率 + 命之座倍率)] × 条件`

条件不满足时 `potentialValue` 仍展示该配置在条件满足时可提供的值，`value` 为零。`actualRestoredValue`
只在有精确生命缺口时给出，避免从不完整的队伍 HP 修正中猜测最大生命。指标不会生成“对当前主 C 的
伤害提升”或跨单位的总评分。

## Consequences

### Positive

- 辅助角色可以在真实队伍和受益目标上下文中结算，而不需要伪装成伤害角色；
- 前端可逐层展示来源属性、天赋值、受益目标修正与条件，不必为每个角色硬编码文案；
- 治疗界面可以在提供生命缺口时明确显示溢出治疗，而不是把理论治疗量错误称为实际恢复；
- 伤害和辅助指标共享统一的结果封装，但各自保持正确的公式和单位；
- 未提供领域位置、当前生命值等必要状态会被明确拒绝，避免静默使用错误假设。

### Negative

- 调用方必须为有目标条件的辅助指标额外提供受益角色状态；
- 每种新辅助能力仍需要实现和审计一个新的强类型公式分支；
- 现有 `/v1/analysis` 仍是伤害分析接口，指标 API 和页面接入需要在后续独立扩展，不能把辅助指标塞进
  有效词条或武器伤害比较接口。

### Neutral

- 当前阶段仍只评价单次核心动作或单次辅助效果，不引入循环、DPS 或用户操作时延模型；
- 队友上下文用于决定辅助效果能否作用及作用多少，不用于固定选择一个主 C 并推导其伤害增量。

## Alternatives Considered

### 继续只计算来源角色的原始数值

Rejected。它无法正确处理受疗加成、领域位置和生命值阈值，也会让“实际收到多少”与展示结果脱节。

### 将每个辅助效果折算为当前主 C 的伤害提升

Rejected。结果高度依赖目标角色、动作、反应、快照与时序，不能代表辅助角色的独立指标。

### 让内容声明任意公式 AST 或 JavaScript 回调

Rejected。早期泛化会使固定版本数据的审计、测试和公式追踪变得不可控。先在真实角色需求驱动下添加
可验证的类型化公式分支。
